# Long_BetterWindows 基础能力 API 手册 (维护准则)

> **当前状态：** 等待功能落地中。
> **原则：** 本手册仅记录已在 `Long_BetterWindows` 宿主中真实实现并验证通过的接口。严禁在开发完成前进行臆测性记录。

---

## API 录入准则

1.  **契约一致性：** 接口名、参数名、返回类型必须与代码中的 `Interface` 或 `Delegate` 完全一致。
2.  **版本控制：** 
    - 任何破坏性变更（Breaking Change）必须提升 API 版本号。
    - 废弃的接口应标记为 `[Deprecated]`，并保留至少两个小版本。
3.  **权限声明：** 每个 API 必须明确标注其对应的 `Capability` 字符串，方便插件在 `manifest.json` 中引用。
4.  **示例代码：** 每个正式录入的 API 必须附带一段 C# 或 JS 的调用示例。

---

## API 录入流程

1.  **开发阶段：** 在宿主程序中实现功能模块。
2.  **验证阶段：** 通过单元测试或 Demo 插件验证 API 的稳定性与权限隔离。
3.  **文档化：** 在本手册中按照以下模版录入：
    - `接口分类.方法名`
    - `权限要求`
    - `参数说明`
    - `返回结果`
    - `异常处理`
