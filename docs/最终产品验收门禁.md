# 最终产品自动验收门禁

最终产品验收以 `verify-final-closure.ps1` 生成的 schema v2 报告为唯一输入，不再读取 reviewer、人工批准回执或签字备注。人工批准脚本和旧回执目录仅作为历史记录保留，不能影响自动验收结论；其删除和归档由 A008 处理。

## 执行顺序

从同一个提交依次执行：

```powershell
$commit = (git rev-parse HEAD).Trim()

.\verify-final-closure.ps1 `
  -ExpectedSourceCommit $commit `
  -OutputPath "artifacts/quality/final-closure/final-closure.json"

.\verify-final-product-acceptance.ps1 `
  -FinalClosureReportPath "artifacts/quality/final-closure/final-closure.json" `
  -SubjectExecutable "src/LongBetterWindows.Host/bin/Release/net8.0-windows/LongBetterWindows.Host.exe" `
  -ExpectedSourceCommit $commit `
  -OutputPath "artifacts/quality/final-product/product-acceptance.json"
```

开发中的跟踪文件尚未提交时可以显式传入 `-AllowDirty`；正式候选不得使用该开关。需要把发布资格作为进程门禁时传入 `-RequireReleaseEligible`：存在环境阻断时仍生成诊断包，但退出码为 `2`。

## 自动合同

聚合器要求并复核：

- 当前 HEAD、参数提交、final closure 和插件矩阵提交完全一致；
- dirty 状态在工作区、final closure 和插件矩阵之间一致；
- final closure 为 schema v2，包含唯一且计数自洽的 94 个自动 gate；
- 25 个插件、42 条命令、25 个场景和 87 个插件 gate 均已执行；
- 不存在 `failed` 或 `not_run` gate；
- 当前 Release 宿主存在，且 SHA-256 与 final closure 完全一致；
- 发布资格与自动 gate 计数、合同状态及 dirty 状态一致。

输出为 schema v3 `automated_final_product_acceptance` 摘要和同名 `.sources/final-closure.json` 闭包副本。摘要记录闭包及 Release 宿主 SHA-256；已有输出或来源目录不可覆盖。

blocked_environment 不是人工待办，也不是产品失败。当前非管理员进程会如实保留 native-performance-preflight 阻断。A007 已把 verify-external-release-gate.ps1 迁移为自动通道策略：unsigned/offline 不要求商业证书或生产 CDN，test service 使用回环 HTTPS 与证书 SHA-256 固定，production 缺少配置时只记录环境阻断。
