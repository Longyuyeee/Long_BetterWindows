# Long_BetterWindows v0.5.0 功能完成总结

## ✅ 已完成功能

### 1. 单文件 .csx/.js/.ts 脚本热插拔 🔥
**状态**: ✅ 完成并编译通过

**改动**:
- `PluginScanner.cs`: 新增 `TryLoadStandaloneJsScriptAsync()` 方法 (+157 行)
- 支持 `.csx` / `.js` / `.ts` 三种单文件格式
- 自动生成虚拟 manifest（C# 脚本 ID: `script-{文件名}`，JS/TS 脚本 ID: `js-{文件名}`）
- JS/TS 脚本自动包装为 HTML 插件，提供完整 `long.*` API 访问
- FileSystemWatcher 监听所有脚本文件变化并热重载

**技术实现**:
```
C# 脚本 (.csx):
  → Roslyn Scripting 直接执行
  → 访问 Host API

JS/TS 脚本 (.js/.ts):
  → 自动生成包装 HTML
  → 创建临时插件目录 .long_temp_{name}
  → WebView2 加载运行
  → 通过 long.* 桥接调用宿主
```

**用户体验**:
```
之前: 创建目录 → 写 manifest.json → 写脚本 → 等待加载 (5 步)
现在: 写 quick-note.js → 拖入 Plugins/ → ✅ 立即生效 (1 步)
```

**示例文档**: `docs/JS_TS脚本示例.md` (+300 行，含 5 个完整示例)

### 5. 架构重构：插件类型松耦合 🏗️
**状态**: ✅ 完成（为 JS/TS 支持铺路）

**改动**:
- `PluginEntry.Instance`: `ILongPlugin` → `object`
- `PluginRegistry.Register()`: 接受 `object` 类型
- 所有调用 `.StartAsync()/.StopAsync()` 的地方增加类型检查：
  - `PluginScanner.cs` (卸载旧版插件)
  - `PluginRegistry.cs` (启用/禁用插件)
  - `LpakInstaller.cs` (卸载插件)

**为什么需要这个改动**:
- `WebPluginRuntime` 不实现 `ILongPlugin`（它是 WebView2 包装器，没有 Start/Stop 概念）
- 允许未来扩展其他运行时类型（如 Python 脚本、Lua 脚本）

**场景 2: 系统管理员快速自动化**
```csharp
// .csx 脚本，熟悉的 C# 语法
await Host.HotKey.RegisterAsync("Ctrl+Alt+L", async () => {
    var logs = Directory.GetFiles(@"C:\Logs", "*.log")
        .OrderByDescending(File.GetLastWriteTime)
        .Take(5);
    
    await Host.Clipboard.SetTextAsync(string.Join("\n", logs));
    await Host.Notification.ShowAsync("最新日志已复制", "success");
});
```
