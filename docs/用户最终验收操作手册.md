# Long助手用户最终验收操作手册

这份手册只告诉验收人需要做什么。测试脚本不会自动替你点击、移动窗口、修改系统设置或判断界面是否好看。

## 一、先理解验收分两轮

### 第一轮：现在就做

在当前收口分支验证：

1. 25 个插件的真实功能；
2. 整体视觉、键盘操作、错误提示和窗口关闭；
3. 任务栏分组、图标和焦点返回的体验观察。

这轮发现问题后仍允许修改代码。

### 第二轮：代码冻结后再做

Draft PR 合入最终发布提交、版本和安装包固定后，再正式验证：

1. 100%、125%、150%、200% 物理 DPI；
2. 高对比度、减少动画、Narrator/NVDA；
3. 管理员 WPR/WPA；
4. GitHub 真实下载、SmartScreen、杀毒软件；
5. 干净 Windows 安装、升级、卸载；
6. 真实 Registry/CDN 部署与回滚。

这些证据必须绑定最终提交或最终候选包。现在提前执行只能作为探索，不能代替第二轮正式证据。

## 二、第一轮开始前

### 1. 准备安全环境

- 关闭包含未保存内容的应用。
- 文件类测试只使用新建的临时目录，不要使用桌面、文档、照片或工作目录。
- Macro 只在记事本等可丢弃目标中录制。
- PortManager 只终止本轮自己启动的临时监听进程。
- WindowManager 不要对系统设置、密码管理器或重要远程会话窗口测试。
- Screenshot 和 ColorPicker 会使用系统剪贴板，先保存剪贴板中的重要内容。

建议建立证据目录：

```powershell
$commit = (git rev-parse HEAD).Trim()
$short = $commit.Substring(0, 7)
$evidence = "artifacts/quality/user-acceptance-$short"
New-Item -ItemType Directory -Path $evidence -Force
```

### 2. 确认机器侧已经就绪

```powershell
.\verify-final-closure.ps1 `
  -OutputPath "$evidence/final-closure.json" `
  -RequireHumanValidationReady
```

必须看到：

- `source_dirty=false`
- `machine_blockers=[]`
- `ready_for_human_validation=true`
- `lpwp_compatibility.valid=true`
- `remaining_human_validation_count=10`（开始验收前的当前基线）

`release_eligible=false` 是正常的，因为你的人工验收尚未完成。

### 3. 启动软件

```powershell
.\start-plugin-validation.ps1
```

脚本会确认输出绑定的是本轮冻结候选，自动选择下一项、创建独立证据目录并启动精确受测 EXE。先查看目录中的
`validation-session.json`，记录受测 EXE 哈希、插件 ID、检查 ID 与 `--open-plugin` 启动参数。软件会直接进入
当前待验插件；这是正常产品打开链路，不是质量探针。正式人工回执不得使用 `.\start-long.ps1` 或
`启动.bat`，因为它们会重新构建开发输出，不能证明操作对象就是冻结 RC。

每完成并提交一份回执后关闭 Long助手，再重新运行会话入口。它会按低、中、高、关键风险顺序自动跳过已有有效回执；若候选之后
出现产品、脚本或普通文档变化，会立即停止并要求重新打包，不会让新源码沿用旧 EXE 的人工结论。

## 三、每个插件都要检查的共同项目

每个插件除了表格中的专项操作，还要确认：

- 能从统一命令中心找到并打开；
- 窗口标题、图标、布局和文字正常；
- 亮色、暗色下没有白底、黑字黑底、裁切或按钮不可读；
- Tab、方向键、Enter、Esc 基本可操作；
- 成功结果明确，失败提示能说明原因；
- 关闭后没有残留窗口、持续占用或重复热键；
- 中文、英文、空输入和非法输入不会导致崩溃；
- 高风险操作在最终执行前有明确预览或确认。

建议每个插件至少保存：

1. 一张打开后的完整界面截图；
2. 一张成功结果截图；
3. 如果涉及动画、取消、拖拽、窗口或输入，保存短视频；
4. 失败时保存错误提示和复现步骤。

文件命名示例：

```text
artifacts/quality/user-acceptance-d5bf5ed/
  base64-open.png
  base64-roundtrip.png
  window-manager-layout.mp4
  window-manager-notes.txt
```

## 四、25 个插件逐项操作

### A. 低风险工具

| 插件 | 检查 ID | 你要做什么 | 通过标准 |
|---|---|---|---|
| Base64 | `encode-decode-roundtrip` | 输入中英文混合文本，编码后再解码 | 解码结果与原文逐字符一致 |
| 硬件监控 | `live-metrics-refresh` | 打开后观察 CPU/内存，连续刷新并关闭重开 | 数值合理，刷新不卡死，不多开残留窗口 |
| JSON 格式化 | `format-minify-invalid` | 格式化和压缩含中文的合法 JSON，再输入非法 JSON | 合法结果正确；非法输入只报错，不覆盖原文 |
| Markdown 预览 | `render-safe-markdown` | 输入标题、表格、链接、代码和中英文文本，再放入简单脚本标签 | 排版正常；不执行危险 HTML/脚本 |
| 密码生成 | `generate-copy-constraints` | 切换长度和字符规则，多次生成并复制 | 长度和规则正确，重新生成有变化，复制内容一致 |
| 正则测试 | `match-groups-invalid-pattern` | 验证多匹配、捕获组，再输入非法表达式 | 匹配与分组正确；非法表达式不冻结 |
| 示例插件 | `hello-settings-language` | 执行 Hello、打开设置、切换语言后再次执行 | 状态保留，语言切换正常 |
| 文本对比 | `unicode-line-diff` | 对比多行中英文文本 | 新增、删除、未变化行区分清楚 |
| 时间戳转换 | `seconds-milliseconds-timezone` | 分别输入秒和毫秒时间戳，来回转换 | 单位判断正确，本地/UTC 标签明确 |
| URL 工具 | `encode-decode-unicode-url` | 编解码包含中文、空格、查询参数的 URL | 来回转换后与原文一致 |
| UUID | `generate-version-format-copy` | 切换支持的版本和格式，多次生成并复制 | 格式正确、结果唯一、复制一致 |

### B. 中风险状态与网络

| 插件 | 检查 ID | 你要做什么 | 通过标准 |
|---|---|---|---|
| 剪贴板历史 | `capture-search-reuse` | 复制两个测试文本，搜索并复用其中一个；重启软件后再检查 | 搜索、复用正确，重启后监听和预期历史正常 |
| 剪贴板工具 | `open-and-transform` | 先复制测试文本，再从命令中心打开，执行一次转换和复制 | 显示内容与剪贴板一致，转换和复制正确 |
| 开发工具箱 | `open-edit-preview` | 新建临时插件文件，修改、预览，然后放弃修改 | 预览不丢编辑内容，放弃后不污染正式插件 |
| 快速笔记 | `create-persist-delete-note` | 创建中英文笔记，重启软件，确认后删除 | 重启后仍存在，删除后不再出现 |
| 翻译 | `online-and-offline-recovery` | 联网翻译固定短句；断网重试；恢复网络后再翻译 | 联网成功，断网提示明确，恢复后无需重启即可成功 |

### C. 高风险隔离操作

| 插件 | 检查 ID | 你要做什么 | 通过标准 |
|---|---|---|---|
| 文件整理 | `isolated-preview-and-apply` | 在新建临时目录放入测试文件，先预览再执行整理 | 预览与最终路径完全一致，目录外文件不变化 |
| 批量重命名 | `isolated-batch-rename` | 在临时目录测试多文件重命名和重名冲突 | 预览准确，冲突被阻止或清楚处理，最终文件名正确 |
| 文件夹备注 | `explorer-edit-reopen` | 给临时文件夹写备注，关闭重开；再对不可访问目标测试失败 | 备注持久化，失败提示明确且不产生错误数据 |
| 端口管理 | `inspect-owned-port` | 启动自己创建的临时监听，查找归属并只终止它 | 进程归属正确，只终止测试监听 |
| 快速启动 | `large-directory-cancel-launch` | 在可删除的大目录中连续更换搜索词，再启动记事本等无害结果 | 新查询替代旧查询，界面保持响应，只启动所选目标 |
| 取色器 | `pick-visible-color` | 对已知纯色区域取色，复制结果；再测试 Esc 取消 | 色值与目标一致，复制正确，取消不改变原剪贴板 |
| 截图 | `full-region-clipboard` | 全屏截图、拖拽区域截图并分别粘贴；再测试 Esc 取消 | 两种图片范围正确，取消保留原剪贴板 |

### D. 关键桌面副作用

| 插件 | 检查 ID | 你要做什么 | 通过标准 |
|---|---|---|---|
| 窗口管理 | `layouts-topmost-multimonitor` | 用记事本测试置顶、左右/角落/三分布局、最小化、多显示器和管理员窗口拒绝；按 `Ctrl+Alt+↑` 后确认进入 Windows 系统最大化，再切换半屏确认恢复普通布局 | 每种布局正确；最大化具有系统最大化状态；失败时恢复原状态；高权限拒绝提示明确 |
| 宏录制 | `record-play-cancel` | 在可丢弃的文本/绘图目标中录制短文本、`Ctrl+A` 等组合键、左键拖拽和右键动作；播放一次，启动/停止循环，再分别在按键和拖拽期间取消 | 文字、组合键、拖拽终点、右键和动作间隔正确；停止及时；结束后无按键或鼠标按钮残留 |

出现以下情况立即停止关键测试：

- 鼠标或键盘持续失控；
- 窗口无法恢复；
- 操作越过临时目录；
- 终止了非测试进程；
- 剪贴板在取消后仍被覆盖。

## 五、如何记录通过或失败

### 通过

逐份查看原图、录像和结果后执行：

```powershell
$sessionEvidence = "artifacts/quality/plugin-manual-<commit>/<当前检查>"
.\complete-plugin-validation.ps1 `
  -Reviewer "你的名字" `
  -Notes "中英文混合文本编码、解码和复制结果一致。" `
  -EvidenceFiles @(
    "$sessionEvidence/base64-open.png",
    "$sessionEvidence/base64-roundtrip.png"
  ) `
  -ConfirmPassed
```

完成脚本从当前已启动会话读取插件 ID、检查 ID、候选提交和受测 EXE，只接受该会话目录内的真实证据；原始
图片和录像仍留在本地。返回 `receipt_created_pending_commit` 后，检查并只提交生成的批准回执。

### 失败

不要运行批准脚本。保存：

- 插件 ID 和检查 ID；
- 你执行的步骤；
- 预期结果；
- 实际结果；
- 是否每次都能复现；
- 截图、录像和日志路径。

把这些内容发给我，我会先复现和修复；源码改变后，受影响项目必须重新验收。

## 七、LPWP 参考 Widget 验收

先从当前提交生成参考包：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\build-reference-widget.ps1 -Force
```

确认输出显示 `验证状态 : passed`、`请求权限 : 无` 和稳定 SHA-256。随后：

1. 在插件市场选择“导入本地 .lpak”，导入
   `artifacts/reference-widget-package/com-long-reference-widgets-v1.1.0.lpak`。
2. 打开“桌面组件”，确认目录出现“专注脉搏”和“灵感计数”。
3. 添加一个“专注脉搏”；再次添加时必须明确提示单实例限制。
4. 添加两个“灵感计数”，分别点击不同次数；两个实例的数字不得互相覆盖。
5. 对实例执行四向移动、增加/减小宽度与高度；冲突、越界和超出 Manifest
   尺寸必须被拒绝，成功布局必须立即更新且页面不能白屏。
6. 切换到其他管理页面再返回，确认 Widget 恢复可见；停留其他页面至少 35 秒
   后返回，确认 suspend/resume 后仍能操作。
7. 关闭并重新启动 Long助手，确认实例位置、尺寸、计数和显示模式恢复。
8. 移除一个实例并重启，确认已移除实例不会回流；最后卸载参考插件，确认无失效
   Widget 卡片残留。
9. 用键盘访问目录添加按钮、实例操作菜单和所有操作；亮暗主题下检查文字、按钮、
   圆角、焦点环、窄窗口重排和状态播报。

至少保存目录、两个多实例计数、移动/缩放后布局、重启恢复和窄窗口各一张截图，
并记录包 SHA-256、源码提交、Windows 缩放比例和是否使用读屏。当前自动化只证明
合同、打包与状态模型正确，不能替代这一轮真实 WebView 验收。

## 八、任务栏与整体视觉观察

打开至少两个不同插件的分离窗口，确认：

- 每个窗口有正确的 Long助手插件图标和标题；
- Windows 任务栏不会把不同插件错误混为同一身份；
- 固定、取消固定、关闭和重新打开行为正常；
- 从插件窗口关闭或返回后，焦点不会丢到桌面；
- 主界面、市场、命令中心、插件窗口在亮暗主题下风格统一；
- 动效帮助理解状态，没有持续晃动、过度缩放或明显卡顿。

把任务栏全景和两个插件窗口截图保存在第一轮证据目录。如果主观上“不够美观”，请圈出具体区域并说明你希望更简洁、突出或紧凑的方向。

## 九、第二轮正式设备与发布验证

第二轮只在我确认“代码冻结、最终提交和新 RC 已生成”后开始。

### 1. 物理 DPI

每个真实缩放档分别运行：

```powershell
$commit = (git rev-parse HEAD).Trim()
.\capture-physical-dpi-evidence.ps1 `
  -OutputDirectory "artifacts/quality/physical-dpi-100-$($commit.Substring(0,7))" `
  -ExpectedScalePercent 100 `
  -ExpectedSourceCommit $commit
```

检查该目录全部截图后，再使用 `approve-physical-dpi-evidence.ps1` 批准。125%、150%、200% 分别执行，不能用系统离屏渲染或 250% 截图替代。

### 2. 辅助功能

先由你在 Windows 设置中启用目标配置，再运行：

```powershell
.\capture-accessibility-evidence.ps1 `
  -OutputDirectory "artifacts/quality/accessibility-high-contrast" `
  -ExpectedProfile high_contrast `
  -ExpectedSourceCommit $commit
```

分别覆盖 `high_contrast`、`reduced_motion`、`combined`。至少一轮使用 Narrator 或 NVDA，并确认焦点公告、按钮名称、动态状态和错误提示。

管理中心专项检查：仅用 `Tab` / `Shift+Tab` 按“概览、工作流、插件、桌面组件、插件市场、系统集成、诊断、开发者、设置”顺序往返；分别用 `Enter` / `Space` 开页；关闭桌面组件、设置和插件市场标签后确认回到管理中心且 MRU 正确。读屏轮次还要确认“关闭桌面组件 / Close Widgets”“关闭设置 / Close Settings”和“关闭插件市场 / Close Plugin Market”。

### 3. 管理员 WPR

在管理员 PowerShell 中运行：

```powershell
.\capture-native-performance-evidence.ps1 `
  -OutputDirectory "artifacts/quality/native-performance-$($commit.Substring(0,7))"
```

随后在 WPA 查看 CPU Usage (Sampled) 与 Desktop Composition。原始 ETL 不上传，把结论、异常模块和关键截图发给我。

### 4. 干净 Windows、真实下载和安装包

使用新用户、另一台电脑或一次性 VM：

1. 从 GitHub Release 页面下载最终 Setup.exe；
2. 不要用本地复制文件替代真实浏览器下载；
3. 记录 SmartScreen 和杀毒软件实际提示；
4. 安装并验证首次启动、托盘、`Alt + Space` 和 WebView2；
5. 覆盖升级并确认设置、笔记和插件数据保留；
6. 卸载并检查快捷方式和系统集成清理；
7. 操作人与最终审核人使用不同身份。

### 5. Registry/CDN

这一项需要受控部署令牌、真实 HTTPS 地址和发布者信任库。不要把令牌、私钥或完整临时下载 URL发到聊天或提交到仓库。到这一步时由我根据最终候选给出精确命令。
