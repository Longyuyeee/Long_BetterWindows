## 三、本轮开发内容审计

### 3.1 组合动作统一入口

新增 `ManagedWorkflowSearchProvider`，只发布本地托管、定义哈希稳定且针对当前插件目录预检有效的工作流。命令中心和超级面板共用 `OpenWorkflowReview` 动作与 `WorkflowReviewNavigation`，打开的是现有权限审查页，而不是绕过批准直接执行。固定和最近使用排序仍然有效。

审计判断：实现符合统一入口目标，也保持了“搜索结果不是伪插件命令”和“执行前再次加载、预检”的安全边界。对应纯逻辑测试覆盖有效工作流、无效定义、哈希变化和动作类型。

### 3.2 展示协调与响应式布局

执行审查、准备失败、执行结果、输出摘要、终端输出和报告详情已提取到 `WorkflowExecutionPresentation`；窗口层主要负责应用投影、焦点、剪贴板和对话框。Tool Center 与工作流编辑器修复了内容宽度不受视口约束、宿主未拉伸和窄窗只裁剪不重排的问题，默认宽屏与 `720 × 560` 紧凑布局已经通过完整桌面套件。

审计判断：职责边界比原来清晰，响应式实现对齐“优雅、扁平且不拥挤”的目标。下一步不应继续把质量状态堆入 `MainWindow`，而应把审查状态和可访问性状态收束为独立模型或 AutomationPeer。

### 3.3 长终端输出与敏感值处理

质量工作流可生成 100 个 UUID，目标输出约 3.7K 字符；终端输出视图使用限高滚动。标题栏增加明确的批准、确认、取消和清除动作，并提供清除快捷键。质量模式报告改写入工作流隔离根下的 `.reports`，不会污染用户 `%LocalAppData%`。

审计判断：产品功能、静态门禁和当前多显示器 250% 缩放环境的真实验收均已闭环。根因不是终端值处理，而是统一入口进入审查时同时物化重型编辑表单，以及长内容 UIA 树与坐标输入不稳定。编辑配置区现已和审查/运行/结果区分离；质量模式改用带 5 秒超时的窗口级消息驱动，仅在显式质量参数下开放。通过证据位于 `artifacts/quality/workflow-long-output-20260723/desktop-ui-smoke.json`。

### 3.4 插件安装事务稳定性

`LpakInstaller` 对 Windows 临时句柄占用造成的目录移动失败增加了最多 6 次、25–800ms 的有限指数退避，安装、卸载、回滚和启动恢复共用同一策略；目标已存在或源消失时不会盲目重试。

审计判断：修复范围受限，没有改变同卷原子移动和事务日志语义，解决了完整测试并行时的真实竞争问题。后续应保留一次安装/卸载并发回归，不扩大为无限重试。

### 设计对齐判断

最初设计要求“宿主-能力-插件”分层、契约优先、宿主中转异步调用和离线安全。当前实现与此一致：宿主集中管理能力和生命周期，插件通过 Manifest 声明命令与权限，组合动作只编排已注册命令，市场和导出路径保留独立审查。下一阶段的参数 Schema 不是新协议，而是补齐现有 `PluginCommandInvocation.Arguments` 自由字典缺失的命令契约，因此应放在 `Contracts` 与无 UI 的统一验证层，ManifestReader、工作流 Planner 和 WPF 编辑器只消费该结果。
