## 共享状态合同

三种面板呈现必须复用同一 `ContextSnapshot`、搜索协调器和偏好数据，不建立三套结果引擎。跨面板状态最少包含：首次唤起前窗口、上下文快照、查询、当前结果 ID。状态仅在内存中一次性交接，消费后清除，不写入日志、JSON、设置或证据文件。

状态流转为：`原应用 -> 紧凑/上下文面板 -> 展开搜索 -> 执行动作或关闭 -> 原应用`。展开动作不得把紧凑面板自身当成原应用，不得重新读取已经变化的剪贴板或前台窗口，也不得在增量搜索首批结果到达时永久覆盖原选择。

## 开发顺序

1. `P1A`（已完成）：完成紧凑/上下文到展开搜索的上下文、查询、选择和原始焦点交接，并用纯合同测试、源码门禁和桌面 UIA 固定。
2. `P1B`（已完成）：将 Super Panel 拆分为紧凑常用网格和上下文关联列表，两者共用会话、分组、分页与动作执行器。
3. `P2A`（已完成）：增加 URL、文本、图片、单文件、多文件和无上下文的确定性桌面 UIA 类型矩阵。
4. `P2B`（已完成）：使用独立前台夹具验证关闭、展开和执行三类退出路径的焦点恢复。
5. `P3`：设置专属分类导航与深链已完成；下一步实现插件详情的命令级关键词、别名、固定、快捷键和启停。
6. `P4`：执行明暗主题、高对比度、物理 DPI、键盘、读屏和真实插件人工验收。

`P1A` 验收要求：展开后上下文项数量和身份不变；原选择存在时恢复，增量首批未出现时继续等待后续批次；`Esc` 和命令执行均使用首次唤起前窗口；敏感交接对象不可序列化有效载荷且只能消费一次。

`P1A` 完成证据：Release 构建 0 警告、0 错误，自动化 1193 / 1193；桌面 UIA 报告确认 `quality.url` 上下文和原结果 ID 均在展开后保留。

`P1B` 完成边界：空上下文及固定/最近/自定义分组使用 12 项紧凑网格；智能推荐在有上下文时使用 6 项关联列表。页码由协调器统一持有，支持按钮与 `PageUp` / `PageDown`，切换上下文或分组回到第一页。250% DPI 网格与 200% DPI 上下文列表已完成真实渲染检查；Release 0 警告、0 错误，自动化 1194 / 1194，桌面 UIA 验证上下文 `1/4 -> 2/4`、空上下文 `compact-grid` 及既有完整工作流。下一步进入 `P2`，扩展文件、图片、文本、多选、无上下文及焦点恢复桌面矩阵。
