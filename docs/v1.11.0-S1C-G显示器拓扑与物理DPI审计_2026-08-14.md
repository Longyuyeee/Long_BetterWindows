# v1.11.0 S1C-G 显示器拓扑与物理 DPI 审计（2026-08-14）

## 结论

当前机器具备两块真实活动显示器，S1C-G 不需要降级为单屏受限验收。真实拓扑变化探针、恢复脚本和自动化门禁已完成开发；双屏收缩/恢复与当前提交的物理 DPI 正式证据尚未执行，因此本阶段仍为“代码准备完成，实机验收待完成”。

## 当前设备边界

- Windows WMI 报告两块活动设备：AOC 2790 与 CSO 1507。
- `\\.\DISPLAY1`：主显示器，2560×1440，工作区 2560×1344，192 DPI（200%）。
- `\\.\DISPLAY2`：副显示器，3840×2160，工作区 3840×2040，240 DPI（250%）。
- 两块显示器均已通过宿主指定设备截图预审，实际设备名与请求设备名一致。

## 需求对齐

- 正式拓扑报告只接受宿主窗口真实收到的 `WM_DISPLAYCHANGE`；质量刷新入口不能生成物理证据。
- 初始拓扑必须至少两屏，原生 `SetDisplayConfig` 切换到 internal 后必须收缩为一屏，切回 extend 后必须恢复初始设备集合。不能依赖只返回成功却可能不应用拓扑的 `DisplaySwitch.exe`。
- 窗口在收缩与恢复后都必须和活动显示器工作区相交，不能留在已移除显示器的不可见区域。
- 硬件监控 WebView 的 session ID、内容身份和嵌入表面必须保持，宿主可见状态必须恢复，结束后插件会话必须清理。
- 异常路径必须尽力恢复扩展模式，并且只终止本次启动的宿主进程树。
- 物理 DPI 证据必须绑定精确干净提交、指定设备名和真实 DPI；200% 与 250% 分别采集亮暗主题及主界面、市场、面板和 Web 插件视图。

## 实现

- `HostEnvironmentStateService` 新增独立 `DisplayTopologyChanged` 事件；`RefreshDisplayForQuality` 不发布该事件。
- `QualityMonitorPlacement` 复用现有 Win32 枚举，向质量探针提供设备、边界、工作区、主屏状态和 DPI。
- `PhysicalDisplayTopologyQualityProbe` 记录初始、缩减、恢复三阶段显示器和窗口状态，并验证 WebView 身份与清理。
- 新增启动参数 `--quality-display-topology-report` 和 `verify-display-topology-recovery.ps1`。
- 定向构建首次发现窗口句柄短路路径的 `out` 变量未显式初始化；修复后定向测试 20 / 20 通过，正式显示拓扑尚未切换。
- Release 全量测试 1440 / 1440 通过，Release 构建 0 警告、0 错误。
