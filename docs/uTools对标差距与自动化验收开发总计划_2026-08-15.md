# Long助手 uTools 对标差距与自动化验收开发总计划

> 制定日期：2026-08-15
> 审计基线：`master@e132c8a0ceaaf3b8601c0f62ef815aa1338e053c`
> 对标样本：本机 uTools 7.5.1、uTools 官方帮助中心与开发者文档
> 产品目标：保留 Long 自有的优雅、华丽、扁平化、动效化视觉，参考 uTools 的软件交互逻辑与插件化产品能力，在 Windows 原生集成、工作区、权限治理和可访问性上继续扩展
> 验收政策：从本文生效起，不再把人工点击、人工截图审阅、人工签字或第二台电脑作为发布资格的必要条件

## 1. 本文的权威性

本文是后续开发的唯一顺序计划。旧文档继续作为历史设计和故障记录，但出现以下冲突时以本文为准：

1. 旧文档要求人工回执、人工签核或独立审阅人时，以本文的自动化验收合同为准；
2. 旧文档把“接近 uTools”理解为复刻界面时，以本文的“逻辑参考、Long 自有视觉”边界为准；
3. 旧文档把插件数量或截图数量当作完成度时，以本文的用户任务、可测行为和质量指标为准；
4. 旧文档要求继续冻结 RC17 时，以本文的 P0 门禁迁移为准。本文属于普通跟踪文件变更，现有 RC17 因不可变候选策略自动成为历史候选，不能直接改名为稳定版；P0 完成后必须生成新候选。

每一个开发批次必须按以下闭环执行：

1. 从本文选择编号最小、依赖已满足的未完成项；
2. 写代码、测试和必要文档，不夹带其他范围；
3. 运行该项列出的自动验收命令并保存机器可读结果；
4. 对照需求、失败边界、隐私和性能进行批次审计；
5. 更新本文状态与当前开发状态；
6. 单独提交并推送；
7. 远端 CI 通过后才进入下一项。

## 2. 不变的产品边界

### 2.1 必须坚持

- 视觉关键词是“优雅、华丽、扁平化、动效化”，不是 uTools 白色界面的像素复制；
- 统一入口必须键盘高效，同时为鼠标、触控板和 Explorer 上下文提供等价路径；
- 插件是核心产品模型，宿主负责身份、能力授权、生命周期、审计、窗口承载和稳定性；
- 本地功能默认离线，网络、AI、同步和市场服务必须显式披露并可关闭；
- 动效必须服务于层级、焦点和状态变化，并在减少动画模式下确定性降级；
- 所有功能必须有自动验收接口，不能把“看起来正常”作为唯一完成定义。

### 2.2 明确不做

- 不实现 uTools 插件兼容层；
- 不复制 uTools 的商标、图标、素材、文案、页面布局或插件包；
- 不读取或逆向用户的 uTools 账号、令牌、私人数据库、剪贴板历史、笔记和浏览记录；
- 不用缓存索引数量伪装成 Long 市场生态规模；
- 不为了“插件多”引入无维护能力、无测试、重复或强依赖在线服务的插件；
- 不用人工签字掩盖不可自动验证的需求。无法自动验证的体验目标必须拆成可观测指标，剩余主观感受只作为非阻断性反馈。

- `Alt + Space` 唤起统一搜索；空查询展示最近使用、已固定和市场精选，查询后展示最佳结果与匹配推荐；

## 4. 总体差距判定

评分采用 0–4：0 为缺失，1 为原型，2 为可用但不完整，3 为产品级对齐，4 为 Long 明确领先。

| 领域 | uTools 参考能力 | Long 当前评分 | 目标评分 | 主要差距 |
|---|---|---:|---:|---|
| 统一唤起 | 即用即走、动态高度、空查询图标入口 | 3 | 4 | 空查询信息架构和窗口轻量感仍可提升 |
| 查询排序 | 最佳匹配、匹配推荐、关键词强调 | 2 | 4 | 缺少稳定的分区合同和统一解释字段 |
| 上下文匹配 | 文本、图片、文件、活动窗口声明式匹配 | 2 | 4 | 正则/图片/活动窗口规则和安全预算不完整 |
| 动态指令 | 运行时增删改 | 0 | 3 | 没有身份绑定、原子清理和持久化策略 |
| 结果回推 | 插件向主入口推送结果 | 2 | 4 | DLL 有搜索提供器，Web/Script 缺统一流式协议 |
| 超级面板 | 文件夹、分页、上下文、语音、整理 | 2 | 4 | 文件夹、分页、键盘等价整理和语音入口缺失 |
| 插件承载 | 嵌入、分离、后台 | 4 | 4 | Long 模型更完整，仍需简化状态表达 |
| 插件开发 | Web 生态、API、调试和发布工具成熟 | 3 | 4 | 动态能力、模拟器、诊断面板和模板体验不足 |
| 市场体验 | 搜索、分类、详情、评论、评分、版本 | 2 | 3 | 安全事务强，但内容发现和生产生态弱 |
| 首方工具覆盖 | 搜索、OCR、图片、PDF、二维码、AI 等 | 2 | 3 | 图片/PDF/OCR/二维码/增强搜索缺口明显 |

| 跨设备与账号 | 同步、会员与团队能力 | 0 | 2 | 需要独立隐私和服务端决策，不阻断本地稳定版 |

## 5. P0：取消全部人工发布门禁，建立纯自动验收

P0 是后续一切开发的前置条件。这里的“取消人工验收”不是降低质量，而是把验收改造成机器可重复、失败可定位、结果绑定提交和产物哈希的合同。

### P0-01 统一验收术语与状态模型

**现状问题**：仓库同时存在 `human_validation`、`manual_checks`、`approval_receipt`、`ready_for_human_validation` 和多套批准脚本；机器已通过仍会因没有签字而失败。

**开发内容**：

1. 新增统一 `automated_acceptance` 模型；状态只允许 `not_run`、`passed`、`failed`、`blocked_environment`、`not_applicable`；
2. `blocked_environment` 不能被误算为通过，是否阻断发布由明确的 channel policy 决定；
3. 删除发布资格对 reviewer、notes、人工 checklist 和 approval receipt 数量的依赖；
4. 报告字段迁移为 `automated_gate_count`、`passed_gate_count`、`failed_gate_count`、`environment_blocked_gate_count`；
5. 保留旧回执只作历史资料，校验器不再读取它们；
6. 所有 JSON Schema、PowerShell、C# 测试和文档同步更新。

**自动验收目标**：

- 仓库发布脚本中不存在参与判定的 `human_validation`、`manual_check`、`reviewer` 或 `approval_receipt_count`；
- 旧回执存在、缺失或损坏均不改变自动验收结果；
- 合同测试覆盖所有状态、非法状态、重复 ID、缺失证据和哈希篡改；
- 生成报告具有提交 SHA、源码 dirty 状态、受测包和 EXE SHA-256。

### P0-02 插件正向矩阵自动化

**现状问题**：25 个插件、42 条命令已有 87 条自动证据，但每个插件仍要求一个人工检查和回执。

**开发内容**：

1. 将 `manual_checks` 迁移为 `acceptance_scenarios`；
2. 每条命令至少覆盖正常输入、空输入、非法输入、取消、超时、重复调用和资源释放中适用的场景；
3. Web 插件使用真实 WebView 桥和 DOM 可观测状态；DLL/Script 使用隔离宿主与能力替身；桌面副作用使用可回滚沙箱目录、虚拟窗口或注入式适配器；
4. 场景输出结构化记录输入摘要、输出类型、状态、耗时、资源清理和副作用摘要；
5. 真实桌面探针只作为机器执行器，不允许出现“待人工观察”。

**自动验收目标**：

- 25/25 插件、42/42 命令至少一个成功场景；
- 所有高风险命令具有失败、取消、回滚和重复执行场景；
- 每个插件连续启动/执行/关闭 3 次，无残留 Worker、WebView 或宿主窗口；
- 测试结果与候选 EXE、插件 Manifest、命令集合和源码提交哈希绑定；
- 任意删除一个场景、篡改一个哈希或新增未覆盖命令都会让门禁失败。

### P0-03 视觉回归自动化

**现状问题**：已有大量截图和 DPI 探针，但部分流程最终仍要求人工“看图签字”。

**开发内容**：

1. 建立稳定场景种子、字体、主题、语言、窗口尺寸和动画时钟；
2. 对主窗口、命令中心、超级面板、市场、设置、开发者工具、工作流和全部 Web 插件生成基准图；
3. 使用感知哈希/结构相似度、关键区域遮罩、OCR 文本框和 UIA 边界联合判断，禁止单纯逐像素比较；
4. 单独检测裁切、重叠、越界、透明异常、空白页、占位图标重复和焦点不可见；
5. 动效验证首帧、运行中关键帧、终帧、持续时间和 reduced-motion 终态。

**自动验收目标**：

- 100%、125%、150%、200%、250% × 亮/暗主题的关键页面矩阵全通过；
- 关键文本 OCR 召回率 100%，关键控件可见面积不低于 95%；
- 禁止关键控件相交、窗口外溢和横向滚动；
- 非关键抗锯齿差异采用经测试确定的容差，关键图标、品牌和焦点框不得被容差隐藏；
- 基准图更新必须由显式 `-UpdateBaseline` 命令完成并输出差异清单，普通测试不得覆盖基准。

### P0-04 可访问性自动化

**开发内容**：使用 UI Automation 自动检查名称、角色、状态、焦点顺序、键盘激活、LiveRegion 事件、高对比度资源、减少动画和窗口返回焦点；读屏器进程存在与否不再是发布门禁。

**自动验收目标**：

- 所有交互控件具备非空 Name、稳定 AutomationId 和正确 ControlType；
- Tab/Shift+Tab 无焦点陷阱，Esc、Enter、Space 和方向键行为有确定性用例；
- 成功、错误、进度和危险确认均产生预期 UIA 事件；
- 高对比度、减少动画和组合模式矩阵自动通过；
- Narrator/NVDA 实际听感可记录为非阻断反馈，但不能改变 `release_eligible`。

### P0-05 安装、升级、卸载与干净环境自动化

**开发内容**：把当前本机安装器生命周期脚本提升为可重复事务；支持临时 Windows 用户、Windows Sandbox 或 CI VM 执行，但没有第二台电脑时允许使用当前机器的隔离用户/目录模型。

**自动验收目标**：

- 首装、覆盖升级、降级拒绝、回滚、卸载、重启恢复和残留扫描全部有退出码与 JSON；
- 测试前后注册表、开始菜单、桌面、安装目录、用户数据和进程差异可核对；
- 失败注入后自动回到旧版本或完全未安装状态；
- SmartScreen 与杀毒软件品牌提示只做非阻断环境记录；包哈希、来源 URL 和签名状态由机器强制验证。

### P0-06 性能与稳定性自动化

**开发内容**：普通 CI 使用 Stopwatch、进程计数器、ETW 可用事件和帧/消息统计；管理员 WPR 作为增强数据源而非唯一门禁。

**自动验收目标**：

- 热唤起 P95 ≤ 180 ms，空查询首屏稳定 P95 ≤ 250 ms；
- 1,000 条候选的查询更新 P95 ≤ 50 ms，主 UI 线程不出现 ≥100 ms 无响应区间；
- 25 插件逐一打开后的宿主空闲私有内存中位数 < 200 MB，并记录最大值；
- 30 次打开/关闭、10 次工作区切换、睡眠/锁屏/显示变化模拟后无残留进程和未处理异常；
- WPR 可用时附加分析，不可用时报告 `not_applicable`，不能伪造数据。

### P0-07 外部服务与设备的确定性策略

生产市场、跨仓库 Long Grid、发布者身份、商业代码签名和云服务无法在每次本地构建中真实执行。处理方式：

- 核心协议、签名、部署、回滚和故障通过本地 HTTPS 测试服务器、固定证书、测试 Registry/CDN 和 fixture 自动验证；
- 真实凭据、真实 CDN、真实签名证书和其他仓库只属于发布通道配置，不属于产品代码完成度；
- 缺少商业 Authenticode 证书时明确发布 `unsigned`，不得阻断 unsigned 通道；
- 外部服务不可用时必须降级、重试或离线，不允许把人工补测写成通过条件。

### P0-08 清理旧入口并重建候选

**完成条件**：

- 删除或归档不再使用的插件人工规划、启动、完成和批准入口；
- 人工回执目录不再参与 CI、打包和候选陈旧白名单；
- `verify-final-closure.ps1` 只汇总自动门禁和明确的外部通道策略；
- 一键验证、一键打包、GitHub Actions 和 README 使用同一命令；
- 从 P0 完成后的干净提交生成新 RC，不复用 RC17 资产。

## 6. P1：统一入口与搜索体验对齐

### P1-01 空查询首页

目标是在保持 Long 视觉的前提下吸收 uTools 的“最近使用、已固定、发现入口”信息架构。

**验收目标**：

- 空查询在 120 ms 内展示最近、固定和建议三个来源；
- 首屏 8–12 个入口，可键盘进入/退出分区，固定与最近不会重复；
- 没有历史时显示有行动价值的空态，而不是空白；
- 100%–250% DPI 下至少完整显示搜索框、一个分区标题和一行入口；
- 用户禁用市场推荐后不发网络请求、不留下空分区。

### P1-02 查询结果分区与解释

分为“最佳匹配、上下文推荐、插件结果、应用与文件、其他建议”，每条结果公开来源、匹配原因、风险和次级动作。

**验收目标**：

- 同一输入、同一索引版本输出顺序确定；
- 最佳匹配最多 1 项，上下文推荐必须说明命中的上下文类型；
- 关键词高亮不破坏屏幕阅读器文本；
- 结果更新时选择项按稳定 ID 保持，删除后移动到最近邻；
- 拼音、别名、前缀、模糊和使用频率分别有排序用例。

### P1-03 自适应窗口与动效

**验收目标**：结果从 0→1→多项→0 时高度平滑变化且焦点不丢失；正常模式动效 160–240 ms，减少动画模式在一帧内进入终态；不得因重排出现闪白、窗口跳屏或跨显示器越界。

## 7. P2：声明式上下文匹配

### P2-01 Manifest 匹配合同

新增版本化 `matchers`，支持：

- `text.regex`、`text.contains`、`text.prefix`，带长度和超时；
- `image`，带 MIME、尺寸和像素上限；
- `file/files/folder`，带扩展名、数量、大小和名称规则；
- `active_window`，带进程名、窗口类和标题规则；
- 旧 `accepted_inputs` 无损映射到默认规则。

**验收目标**：Schema、解析、SDK、Web SDK、开发模板、文档和错误消息同步；灾难性正则在预算内终止；插件无能力时不得获得原始敏感上下文。

### P2-02 匹配执行与排序

**验收目标**：单插件规则预算 ≤5 ms，全量 25 插件 P95 ≤30 ms；慢规则隔离并降权，不阻塞 UI；相同规则结果确定；输入只以摘要进入日志，原始图片、文件内容和剪贴板默认不落盘。

### P2-03 活动窗口与 Explorer 上下文

**验收目标**：浏览器、编辑器、Explorer 和普通桌面窗口 fixture 均能精确匹配；标题变化、进程退出和权限不足可恢复；Explorer 多选在 0、1、N 项和超大集合下均有限额。

## 8. P3：动态指令与结果回推

### P3-01 动态指令生命周期

插件可以注册、更新、撤销临时指令；宿主强制绑定插件身份和会话。

**验收目标**：插件停止、崩溃、升级、卸载和热重载后动态指令原子清理；不能覆盖其他插件或宿主命令；单插件数量、标题、图标和更新频率有限额；重放相同操作幂等。

### P3-02 结构化结果流

统一 Web、Script、DLL 的结果协议，支持文本、列表、进度、错误、预览、取消和次级动作。

**验收目标**：首批结果 P95 ≤100 ms；取消后不再更新 UI；过期会话结果被拒绝；每批结果有稳定 ID；最多结果数、单项大小和总大小均有限额；异常插件不能拖垮搜索。

### P3-03 结果回推与工作流

动态结果可固定、进入最近、触发组合动作或返回插件，但必须经过能力授权和风险审查。验收覆盖来源身份、参数 Schema、撤销、失败补偿和审计记录。

## 9. P4：超级面板深化

### P4-01 文件夹、分页和布局

**验收目标**：拖拽合并、拆分、重命名、排序、移除和分页均有鼠标与键盘等价路径；布局持久化具备版本迁移和损坏回退；20、100、500 个入口下交互 P95 ≤50 ms。

### P4-02 上下文头部结果

对可确定的文本、颜色、时间戳、URL、图片尺寸和文件摘要显示即时结果，不自动上传内容。

**验收目标**：本地规则 100 ms 内完成；不匹配时不占位；敏感上下文不写日志；结果可以复制、打开或发送到插件；失败不会阻断固定入口。

### P4-03 语音入口

语音属于可选增强。必须先确定本地/在线提供器、权限、隐私、取消和文本回填合同。没有提供器时界面不展示失效入口；在线语音不得默认启用，也不阻断 v1.12。

## 10. P5：插件开发与市场体验

### P5-01 开发者诊断中心

展示 Manifest 校验、能力调用、桥消息、生命周期、内存、异常和动态指令；支持导出脱敏诊断包。

**验收目标**：一个错误能定位到插件、命令、字段或能力；诊断包不含剪贴板正文、文件内容、令牌和用户路径；调试开关不影响 Release 默认性能。

### P5-02 模板与契约测试

Web、Script、DLL 模板都必须包含主题、双语、键盘、取消、错误、生命周期和自动场景；`new-plugin.ps1` 生成后无需手改即可通过基础 CI。

### P5-03 市场信息架构

补齐分类、搜索建议、详情、版本记录、权限摘要、签名身份、安装/运行状态、更新与回滚入口。评分评论只有在具备真实账号、服务端防滥用和隐私策略后实现；在此之前明确标记为“未提供”，不得用假数据占位。

### P5-04 可信安装体验

**验收目标**：安装前展示发布者、版本、权限增量和签名；升级时显示变更；失败自动回滚；后台运行状态和结束运行入口实时一致；离线、证书错误、哈希错误和并发安装均有自动场景。

## 11. P6：首方插件能力补齐

按用户价值、离线性、风险和对标差距排序，不以数量为目标。

### P6-01 图片基础工具

支持图片上下文打开、尺寸查看、格式转换、压缩、缩放、裁剪和复制/另存。验收覆盖 PNG/JPEG/WebP/GIF/SVG 的适用子集、透明通道、EXIF 方向、超大图限额、批处理取消和源文件不覆盖策略。

### P6-02 二维码助手

文本生成二维码，图片/截图识别二维码。验收覆盖中文、URL、长文本、低对比度、旋转、无二维码、多二维码和恶意超大图片；默认离线。

### P6-03 PDF 基础处理

第一批只做离线合并、拆分、旋转、提取页面和转图片。验收覆盖加密 PDF 的明确拒绝、损坏文件、超大文件预算、输出原子写入和取消清理。Office 格式转换不在第一批承诺内。

### P6-04 增强本地搜索

优先 Windows Search，Everything 作为用户显式安装的可选适配器。验收覆盖索引不可用、权限拒绝、网络盘、隐藏文件、结果去重、取消和 10 万条 fixture 性能；不得捆绑未授权第三方组件。

### P6-05 OCR

OCR 单独立项评估模型许可、包体、CPU/内存、中文准确率和隐私。目标样本集必须版本化；中文印刷体字符准确率目标 ≥95%，失败时保留原图且不上传。未选定合规模型前不得宣称已对齐。

### P6-06 自动化助手增强

在现有 Macro 和组合动作上增加可视化步骤、条件、循环、变量和可撤销动作；键鼠模拟必须有显式授权、紧急停止和最大运行时长。验收覆盖循环上限、取消、窗口丢失、权限变化、失败补偿和敏感输入脱敏。

## 12. P7：中长期能力，不阻断本地稳定版

| 能力 | 前置决策 | 自动验收目标 |
|---|---|---|
| AI 助手 | 提供器、费用、密钥存储、联网提示 | 模型适配器契约、流式取消、工具权限、敏感数据默认不发送 |
| 跨设备同步 | 账号、服务端、加密和冲突策略 | 端到端加密 fixture、离线编辑、冲突合并、设备撤销、导出删除 |
| 团队与私有市场 | 身份、组织、审计和计费 | 租户隔离、权限矩阵、签名发布、回滚和审计日志 |
| 生产评论评分 | 账号、防刷、内容治理 | 真实后端、分页一致性、举报、删除、隐私与滥用测试 |
| 商业代码签名 | 证书采购和保管 | CI 密钥隔离、签名验证、时间戳、吊销和应急轮换 |

这些能力未完成时，产品必须诚实隐藏或标注，不得阻断 `unsigned + local-first` 发布通道。

## 13. 横向质量标准

所有 P1–P7 功能都必须同时满足：

1. **视觉**：Long Design System token，不出现局部仿 uTools；亮暗主题、高对比度和 100%–250% DPI；
2. **动效**：有进入、退出、排序、进度和反馈语义；减少动画模式确定性降级；
3. **键盘**：完整主流程、可见焦点、无陷阱、快捷键不冲突；
4. **可访问性**：UIA Name/Role/State、LiveRegion、对比度和焦点恢复自动通过；
5. **国际化**：`zh-CN` / `en-US` 对称，长英文不裁切，不在代码硬编码业务文案；
6. **隐私**：最小能力、默认本地、敏感数据不落日志、网络调用可观察；
7. **安全**：输入限额、超时、取消、路径约束、原子写入、签名和哈希；
8. **生命周期**：启动、隐藏、分离、后台、停止、崩溃、升级和卸载无残留；
9. **性能**：为热路径设置 P50/P95 和资源预算，不接受只报告平均值；
10. **可测试性**：没有自动场景和机器可读证据的功能不得标记完成。

## 16. 最终收口定义

只有同时满足以下条件，才能说“已经接近收口，可以交给用户体验验证”：

- P0 全部完成，仓库没有人工签字型发布门禁；
- P1–P5 全部完成，统一入口、匹配、动态结果、超级面板和开发者/市场主链路达到目标；
- P6 至少完成图片、二维码、PDF 和增强本地搜索，正式插件具有图片上下文消费者；
- 构建、全量测试、25 插件/42 命令矩阵、视觉、可访问性、性能、生命周期、安装器、升级和卸载自动门禁全部通过；
- 新候选从干净提交生成，包、Manifest、安装器、EXE 和更新元数据哈希一致；
- README、用户指南、插件开发指南和发布说明与真实功能一致；
- 没有把缺少第二台电脑、人工签字、商业证书、真实市场账号或其他外部仓库伪装成产品代码缺陷；
- 所有未完成外部能力都有明确隐藏、降级或延期策略。

## 17. 当前结论与下一步

Long助手没有偏离最初方向，但还没有完全对齐 uTools。当前优势是 Windows 原生工作区、组合动作、能力治理、可信事务、生命周期和可访问性；核心落后项是声明式内容匹配、动态指令、Web/Script 结果回推、超级面板整理深度、图片/PDF/OCR/增强搜索覆盖、市场内容发现和生态规模。

A001-A007 已完成并通过远端 CI。下一步执行 **A008：删除或归档插件人工批准入口**。P0 完成前不继续 RC17 人工回执，不新增插件，不发布稳定版。

### 18.1 任务状态规则
