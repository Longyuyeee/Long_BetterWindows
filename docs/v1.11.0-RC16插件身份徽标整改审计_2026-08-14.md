# v1.11.0 RC16 插件身份徽标整改审计（2026-08-14）

## 1. 本阶段目标

RC15 最终视觉预审确认：Command Palette 与超级面板对缺少图片资源的插件反复显示同一个通用十字占位图标。该表现不会破坏功能，但削弱了高频入口的插件辨识度和产品完成感，与“优雅、华丽、扁平化、动效化”以及参考 uTools 的快速识别逻辑仍有差距。

本阶段严格按 RC15 决策收口，只修复插件视觉身份回退，不增加 uTools 插件兼容层、不改变插件协议、不启用生产 Worker，也不扩展 v1.11.0 功能范围。

## 2. 实现与边界

- 真实插件图片仍拥有最高优先级，已有 `IconPath` 时不显示文字徽标。
- 仅 `Plugin` 类型且没有图片的结果显示首字徽标；管理、设置、文件等系统结果继续使用既有矢量图标。
- 徽标优先取插件来源名，来源缺失时回退到命令标题。
- 首字使用 Unicode 文本元素而非 UTF-16 单字符，兼容中文、拉丁字母和 emoji；拉丁字母统一大写。
- Command Palette 与超级面板共享同一数据语义和视觉规则，使用强调色柔和底色、强调色描边与扁平圆角。
- 徽标是装饰元素，不创建 UI Automation Peer，不重复朗读结果名称；原结果标题、位置播报和键盘路径保持不变。

涉及的核心文件：

- `src/LongBetterWindows.Host/Interaction/SearchModels.cs`
- `src/LongBetterWindows.Host/Interaction/LauncherResultProjection.cs`
- `src/LongBetterWindows.Host/Controls/DecorativeTextBlock.cs`
- `src/LongBetterWindows.Host/Views/CommandPaletteWindow.xaml`
- `src/LongBetterWindows.Host/Views/SuperPanelWindow.xaml`

实现过程中曾尝试使用不属于 WPF 的 `AutomationProperties.AccessibilityView`，编译器立即以 `MC3072` 拒绝；该尝试未提交，随后改为无 Automation Peer 的专用装饰文本控件。最终构建与测试均已证明修正路径有效。

## 4. 版本与候选策略

应用、安装器、发布脚本、测试夹具和面向用户文档已同步提升到 `1.11.0-rc.16`；Windows 数字文件版本继续保持 `1.11.0.0`。RC15 资产保持不可变，历史审计中的 RC15 字样不做伪造性替换。

本次提交进入 PR 并通过分支 CI、合并和主分支 CI 后，才从精确干净的合并提交生成 RC16 双 ZIP、unsigned 当前用户安装器、Manifest 与哈希。开发目录构建和本次截图不能代替候选资产门禁。

## 5. 对标结论与下一步

本阶段已关闭 RC15 发现的高频入口视觉阻断：无图插件现在具备稳定、简洁、可快速扫视的身份标记，交互信息层级更接近对标产品，同时保留 Long助手自己的扁平强调色设计和可访问性优势。

下一步严格顺序：

1. 提交、推送并通过 PR CI，合并后复核主分支 CI。
2. 从精确干净的 RC16 合并提交重新打包全部候选资产并执行结构、哈希、命令、WebView2 与安装器门禁。
3. 对 RC16 实物复跑完整桌面与最终视觉预审。
4. 若不再发现代码问题，继续 25 / 25 插件人工回执、真实读屏、托盘/任务栏和可获得的最高强度隔离验收。
5. 所有最终门禁通过或按既定政策明确批准延期后，才冻结正式 `1.11.0`。

当前结论：**RC16 整改代码已通过本地工程、视觉与桌面自动化验收；候选资产与人工/隔离门禁尚未完成，因此尚不能标记稳定版收口。**
