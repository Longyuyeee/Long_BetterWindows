# P0-A001 自动验收状态合同

## 目标

A001 只建立 `automated_acceptance` v1 状态、Schema 和合同测试，不删除旧脚本，不修改插件功能，也不生成新的发布候选。

## 状态

只允许以下状态：

- `not_run`：尚未执行；
- `passed`：执行完成且符合预期，至少绑定一份哈希证据；
- `failed`：执行完成但实际结果不符合预期，至少绑定一份哈希证据；
- `blocked_environment`：外部环境无法提供，必须记录具体阻断原因；
- `not_applicable`：当前通道不适用，必须记录具体原因。

`blocked_environment` 不是通过。它是否阻断发布由后续 A007 的 channel policy 决定。

## 报告边界

报告必须绑定 40 位 Git 提交、源码 dirty 状态、受测 package 与 EXE 的 SHA-256。每个 gate 必须包含稳定 ID、状态、摘要和证据集合；通过与失败必须有证据，环境阻断与不适用必须有原因。Schema 拒绝未知字段和不符合格式的哈希。

JSON Schema 无法按对象属性表达数组内 ID 唯一性，因此所有生产消费者还必须拒绝重复的 gate、artifact 和 evidence ID。A001 合同测试固定该语义，后续聚合器迁移时复用同一规则。

## 旧字段迁移映射

| 旧字段/入口 | 新合同目标 | 迁移批次 |
|---|---|---|
| `manual_checks` | `acceptance_scenarios` | A002 |
| `approval_receipt_count`、人工回执索引 | 自动 gate 计数与哈希证据 | A003-A004 |
| `ready_for_human_validation`、`human_validation` | `automated_acceptance.gates` | A005 |
| `reviewer`、`notes`、最终人工批准 | 不参与发布资格；旧资料只归档 | A006-A009 |
| 外部设备、证书和服务人工结论 | `blocked_environment` 加 channel policy | A007 |

在对应批次完成前，旧入口保持兼容但不得扩展。A001 新 Schema 也暂不接管最终发布判定。

## 真实合同测试

测试使用 JsonSchema.Net 直接加载 [`../schemas/automated-acceptance.schema.json`](../schemas/automated-acceptance.schema.json) 并评估 JSON 实例，不以字符串包含断言代替 Schema 执行。正例覆盖五种状态；反例覆盖非法状态、根字段和 gate 字段缺失、环境/不适用原因缺失、package/EXE 绑定缺失、哈希格式错误以及重复 ID 语义。

## 本批执行审计

- 批次编号：A001；
- 需求目标：建立统一自动验收状态与 Schema，不迁移旧消费者；
- 对标差距：移除“机器已通过但仍等待人工签字”的数据模型前置障碍；
- Long 自有扩展：报告强制绑定源码 dirty 状态、package、EXE 与证据 SHA-256；
- 代码范围：Schema、合同测试、测试依赖、共享证据 SHA-256 和最终聚合器共享入口；
- 新增自动场景：11 项 Schema/语义正反例；
- 预期结果：A001 专项全部通过，既有完整套件无回归；
- 首次实际结果：专项先暴露 JsonSchema.Net 输入类型和重复注册差异，修正后 `11 / 11`；首次完整套件 `1422 / 1478`，56 项失败集中在 Windows PowerShell `Get-FileHash` 自动加载和两个并发 TCP 超时；
- 差异修正：Schema 按库要求构建一次、多次评估；共享证据层改用 .NET SHA-256 确定性实现，最终聚合器复用同一入口；串行复核确认 TCP 测试 `6 / 6`；
- 最终实际结果：Release 完整自动化 `1478 / 1478`，0 失败，约 2 分 23 秒；
- 性能结果：本批不改变产品运行时；只记录完整测试耗时，不据此替代 P0-06 性能门禁；
- 隐私/权限/回滚：仅读取本地测试文件并计算哈希，不新增网络、权限或持久化；
- 候选与产物哈希：本批不生成候选；RC17 保持历史候选；
- 提交与远端 CI：以本批推送后的共同 HEAD 为准，CI 通过前状态为 `in_progress`；
- 下一批入口：本批远端两个 CI Job 均通过后进入 A002。
