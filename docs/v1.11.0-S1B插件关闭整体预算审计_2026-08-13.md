## 1. 本批目标

本批只处理稳定版总计划的 S1B，不修改 UI、版本号、插件协议或 unsigned 发布政策。目标是在保留单插件 3 秒预算和串行启动清理的前提下，为全部插件增加 20 秒硬预算，避免 25 个失联插件把退出时间累积到约 75 秒。

## 2. 实现结果

1. `PluginRegistry.ShutdownAllAsync` 同时接受单插件预算和整体预算。
2. 每个插件实际等待预算取“单插件预算”和“整体剩余预算”的较小值。
3. 整体预算耗尽后不再启动剩余插件的清理，并以 `skipped_total_budget` 结构化记录每个未启动插件。
4. 返回 `PluginShutdownReport`，包含总耗时、整体预算、每插件状态/耗时/等待预算和全部未完成插件 ID。
5. 保持顺序遍历，没有引入 `Task.WhenAll` 或主动并行关闭。
6. 已经开始但超时的插件继续由迟到观察器接管，不重新修改 Registry 状态、健康状态、自动启动偏好或 UI。
7. 插件关闭不完整时，`ShutdownAllForHostAsync` 抛出不包含插件私密错误正文的稳定异常，使 S1A 顶层 `plugins` 步骤如实成为 `failed`；`BestEffortShutdownSequence` 仍继续执行 Plugin Runtime 和 Host Services。
8. 正式宿主固定使用单插件 3 秒、整体 20 秒预算。
