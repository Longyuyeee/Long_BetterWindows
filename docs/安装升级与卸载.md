# Long助手 安装、升级与卸载

> 适用版本：v1.11.0-rc.2
> 当前分发形态：Windows x64 按用户安装包 + 便携包

## 1. 选择下载包

| 包 | 适合用户 | 额外依赖 |
|---|---|---|
| `LongAssistant-Setup-*.exe` | 推荐，普通用户安装、升级与卸载 | WebView2 Runtime |
| `self-contained.zip` | 免安装或便携使用 | WebView2 Runtime |
| `framework-dependent.zip` | 已安装 .NET、希望包更小的便携用户 | .NET 8 Desktop Runtime x64、WebView2 Runtime |

Windows 11 通常已经包含 WebView2 Runtime；若 Web 插件无法打开，请从 Microsoft 官方渠道安装 Evergreen WebView2 Runtime。

## 2. 校验下载文件

将安装包或 ZIP 与 `SHA256SUMS.txt` 放在同一目录，在 PowerShell 中执行：

```powershell
Get-FileHash .\LongAssistant-Setup-v1.11.0-rc.2.exe -Algorithm SHA256
```

输出哈希必须与 `SHA256SUMS.txt` 中对应文件完全一致。当前采用公开的 `unsigned` 分发通道，Windows 可能显示未知发布者或 SmartScreen 提示；这不等于哈希校验可以省略。

发布审核人员可在启动程序前采集下载来源证据：

```powershell
.\capture-release-download-evidence.ps1 `
  -DownloadedPackage "$HOME\Downloads\LongBetterWindows-v1.9.0-win-x64-self-contained.zip" `
  -ReleaseManifest ".\artifacts\releases\v1.9.0\release-manifest.json" `
  -ExpectedSourceCommit "d3cd956c1a29a5ddc9b8f40031c3e6abdcbf93b4" `
  -ExpectedDistributionChannel unsigned `
  -OutputPath ".\artifacts\quality\release-download-v1.9.0-rc.1\download-evidence.json"
```

脚本会验证 Manifest、提交、通道、文件大小、SHA-256 和 Windows `Zone.Identifier`，并只记录脱敏后的 HTTPS 主机与路径。它不会解压或启动程序，也不会把 SmartScreen、杀毒软件或首次启动标记为已通过。

人工完成解压、来源标记、SmartScreen、杀毒软件和首次启动观察后，由不同的审核人执行批准脚本：

```powershell
.\approve-release-download-evidence.ps1 `
  -EvidencePath ".\artifacts\quality\release-download-v1.9.0-rc.1\download-evidence.json" `
  -ExpectedSourceCommit "d3cd956c1a29a5ddc9b8f40031c3e6abdcbf93b4" `
  -ExpectedDistributionChannel unsigned `
  -Operator "<实际操作人>" -Reviewer "<独立审核人>" `
  -ExtractionMethod "<实际解压方式>" `
  -SmartScreenObservation "<实际提示或未出现提示>" `
  -AntivirusObservation "<实际扫描结果>" `
  -FirstLaunchObservation "<实际首次启动结果>" `
  -ReviewNotes "<审核备注>" `
  -ConfirmExtractionCompleted -ConfirmExtractedExecutableOriginChecked `
  -ConfirmSmartScreenObserved -ConfirmAntivirusObserved -ConfirmFirstLaunchObserved `
  -OutputPath ".\artifacts\quality\release-download-v1.9.0-rc.1\download-approval.json"

.\verify-release-download-evidence.ps1 `
  -EvidencePath ".\artifacts\quality\release-download-v1.9.0-rc.1\download-evidence.json" `
  -ApprovalPath ".\artifacts\quality\release-download-v1.9.0-rc.1\download-approval.json" `
  -ExpectedSourceCommit "d3cd956c1a29a5ddc9b8f40031c3e6abdcbf93b4" `
  -ExpectedDistributionChannel unsigned `
  -OutputPath ".\artifacts\quality\release-download-v1.9.0-rc.1\download-gate-summary.json"
```

批准文件与汇总文件必须来自实际观察，不能使用示例或自动化测试占位内容。验证器会拒绝证据被修改、候选身份不一致、操作人与审核人相同或人工清单不完整的情况。

全部外部门禁分别通过后，使用统一决策器核对它们是否属于同一候选：

```powershell
# 先只读预检：使用下方相同输入，省略 OutputPath 并添加 -PreflightOnly
.\verify-external-release-gate.ps1 `
  -ReleaseManifestPath "<候选 release-manifest.json>" `
  -DownloadGatePath "<download-gate-summary.json>" `
  -CleanEnvironmentGatePath "<clean-environment-gate-summary.json>" `
  -PhysicalDpiGatePath "<physical-dpi-gate-summary.json>" `
  -AccessibilityGatePath "<accessibility-gate-summary.json>" `
  -MarketplaceRehearsalPath "<rehearsal-summary.json>" `
  -ExpectedSourceCommit "<完整 40 位候选提交>" `
  -ExpectedDistributionChannel unsigned `
  -PreflightOnly

# 预检通过后才生成不可覆盖的正式决策
.\verify-external-release-gate.ps1 `
  -ReleaseManifestPath "<候选 release-manifest.json>" `
  -DownloadGatePath "<download-gate-summary.json>" `
  -CleanEnvironmentGatePath "<clean-environment-gate-summary.json>" `
  -PhysicalDpiGatePath "<physical-dpi-gate-summary.json>" `
  -AccessibilityGatePath "<accessibility-gate-summary.json>" `
  -MarketplaceRehearsalPath "<rehearsal-summary.json>" `
  -ExpectedSourceCommit "<完整 40 位候选提交>" `
  -ExpectedDistributionChannel unsigned `
  -OutputPath "<external-release-gate-decision.json>"
```

统一决策器不会代替采集和人工批准。它要求下载、干净环境、物理 DPI、可访问性及完整 HTTPS Registry 演练摘要全部通过，并核对源码提交、`unsigned` 通道、包文件、SHA-256、独立操作/审核身份、Registry 最后提交、公开验证与回滚验证。下载、批准和干净环境来源在哈希复算后还会解析 JSON 并与摘要交叉核对，不能只手工更新哈希。门禁自身的 `-PreflightOnly` 只输出 `external_release_gate_preflight` JSON，禁止指定输出路径且不会生成正式决策。输入文件的 SHA-256 会写入最终决策；正式决策通过同目录临时文件和原子重命名完整落盘，输出路径已存在或发生并发写入时拒绝覆盖并清理临时文件。Registry 演练器的 `PreflightOnly` 结果仍不能作为完整部署回滚演练使用。

## 3. 安装与首次启动

### 3.1 Setup.exe（推荐）

1. 运行 `LongAssistant-Setup-v1.11.0-rc.2.exe`。
2. 安装器默认写入 `%LOCALAPPDATA%\Programs\LongAssistant`，不请求管理员权限。
3. 安装器创建开始菜单入口；桌面快捷方式由用户在向导中选择。
4. 安装结束后可直接启动 Long助手，并可在 Windows“已安装的应用”中执行标准卸载。

### 3.2 便携 ZIP

1. 将 ZIP 解压到当前用户可写目录，例如 `%LOCALAPPDATA%\Programs\LongAssistant-Portable`。
2. 不要直接放入需要管理员写权限的 `Program Files`。
3. 运行 `LongBetterWindows.Host.exe`。

首次启动后确认托盘图标存在，并使用 `Alt + Space` 打开命令中心；如果该热键已被其他软件占用，宿主会尝试 `Ctrl + Alt + Space`。

## 4. 数据位置

| 数据 | 默认位置 | 升级时处理 |
|---|---|---|
| 内置和第三方插件 | `<应用目录>\Plugins` | 保留第三方插件，更新内置插件 |
| 插件 Key-Value 数据 | `<应用目录>\config\storage.json` | 必须保留 |
| 日志 | `<应用目录>\logs` | 可删除 |
| 主题设置 | `%LOCALAPPDATA%\LongBetterWindows\theme.json` | 保留 |
| 文件夹备注 | 对应 NTFS 文件夹的 ADS 数据流 | 不随应用卸载自动删除 |
| 兼容旧右键菜单等集成 | 当前用户注册表 | 卸载前在 Tool Center 中关闭 |
| Win11 一级右键菜单 | 当前用户 Sparse Package + `%LOCALAPPDATA%\LongBetterWindows\Integration` 收据 | 移动或删除应用目录前必须先在 Tool Center 卸载 |

## 5. 升级

### Setup.exe

1. 从托盘菜单彻底退出 Long助手。
2. 备份 `<应用目录>\config` 和自行安装的第三方插件。
3. 校验新 Setup.exe 的 SHA-256，并直接运行；相同 AppId 会复用原安装目录完成覆盖升级。
4. 验证命令中心、托盘、热键和常用插件。

### 便携 ZIP

1. 从托盘菜单彻底退出 Long助手。
2. 如果启用了“Win11 一级右键菜单”，先在原目录的 Tool Center 卸载。
3. 备份 `<应用目录>\config` 和所有自行安装的第三方插件目录。
4. 校验新 ZIP 的 SHA-256，并解压到新目录。
5. 复制原有 `config` 和第三方插件后启动验证，再删除旧目录。

候选阶段的便携包推荐“新目录并行升级”，以便快速回滚。

## 6. 回滚

1. 退出当前版本。
2. 启动升级前保留的旧目录中的 `LongBetterWindows.Host.exe`。
3. 如新版本写入过配置，可将备份的 `config` 恢复到旧目录。
4. 插件 Manifest 新字段均提供兼容默认值，但回滚前仍建议保留插件备份。

## 7. 卸载

1. 在 Tool Center 的“系统集成”中分别卸载“Win11 一级右键菜单”、关闭“兼容旧右键菜单”、开机自启和其他已启用集成；两个右键菜单通道互不替代。
2. 从托盘彻底退出应用。
3. Setup.exe 用户在 Windows“已安装的应用”中卸载“Long助手”；便携用户直接删除应用目录。
4. 如需删除主题设置，可删除 `%LOCALAPPDATA%\LongBetterWindows`。
5. 如需彻底清理当前用户注册表配置，可检查并删除 `HKCU\Software\LongBetterWindows`。

删除应用不会自动删除已经写入各文件夹 NTFS ADS 的备注数据。

## 8. 发布验收：干净 Windows 用户环境

正式发布前必须在新建 Windows 用户或一次性虚拟机中验收候选 ZIP。源码构建目录、长期使用的开发账户和只做进程冒烟都不能替代本门禁。

### 8.1 采集自动证据

进入仓库根目录，在候选包从未启动、Long助手进程未运行时执行：

```powershell
.\capture-clean-environment-evidence.ps1 `
  -ReleaseZip .\artifacts\releases\v1.9.0\LongBetterWindows-v1.9.0-win-x64-self-contained.zip `
  -ReleaseManifest .\artifacts\releases\v1.9.0\release-manifest.json `
  -ExpectedSourceCommit "完整的 40 位候选源码提交" `
  -ExpectedDistributionChannel unsigned `
  -OutputDirectory .\artifacts\quality\clean-windows-v1.9.0 `
  -EnvironmentLabel "Windows 11 24H2 disposable VM" `
  -ConfirmCleanUserEnvironment
```

脚本会校验 Release Manifest、分发通道与 ZIP 哈希，解压真实候选包，检查 25 个唯一插件和 42 条命令，执行真实命令与完整桌面 UI/WebView2 冒烟，并把机器、用户 SID、系统版本和证据哈希写入清单。它不会自行断言账户“干净”，缺少 `-ConfirmCleanUserEnvironment` 时会直接拒绝。`unsigned` 通道要求 `signed=false`，`signed` 通道要求 `signed=true`；两者都必须记录 `release_eligible=true`，不能跨通道复用证据。

### 8.2 人工生命周期验收

自动采集结束后，由另一名验收者按第 3—7 节完成以下检查：首次启动、托盘图标、全局热键、WebView2 插件、新目录并行升级与数据保留、旧版本回滚、卸载及系统集成清理。批准脚本会拒绝使用采集账户名作为审核人。全部通过后执行：

```powershell
.\approve-clean-environment-evidence.ps1 `
  -EvidenceDirectory .\artifacts\quality\clean-windows-v1.9.0 `
  -ExpectedSourceCommit "完整的 40 位候选源码提交" `
  -ExpectedDistributionChannel unsigned `
  -Reviewer "reviewer-name" `
  -ReviewNotes "已在一次性虚拟机完成完整便携版生命周期验收" `
  -ConfirmFirstStart -ConfirmTrayIcon -ConfirmGlobalHotkey -ConfirmWebViewRuntime `
  -ConfirmParallelUpgradeDataPreserved -ConfirmRollbackToPreviousVersion `
  -ConfirmUninstallIntegrationsRemoved
```

最后汇总门禁：

```powershell
.\verify-clean-environment-evidence.ps1 `
  -EvidenceDirectory .\artifacts\quality\clean-windows-v1.9.0 `
  -ExpectedSourceCommit "完整的 40 位候选源码提交" `
  -ExpectedDistributionChannel unsigned `
  -OutputPath .\artifacts\quality\clean-windows-v1.9.0\clean-environment-gate-summary.json
```

采集与汇总会同时核对 Release Manifest、证据和操作员指定的完整源码提交，拒绝把其他候选的干净环境结果用于本次发布。人工批准在独占审核锁内复核 Manifest 原始哈希并原子替换；批准期间文件变化或并发审核会被拒绝。v2 汇总必须与 `clean-environment-evidence.json` 位于同一目录，供最终门禁重新计算来源哈希；汇总文件使用不可覆盖的原子写入，已有路径会被拒绝。证据文件缺失、哈希被修改、自动检查失败、缺少人工批准或任一生命周期项目未确认时，门禁都会拒绝通过。
