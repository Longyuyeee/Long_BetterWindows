# Long窗口 安装、升级与卸载

> 适用版本：v1.9.0
> 当前分发形态：Windows x64 便携包

## 1. 选择下载包

| 包 | 适合用户 | 额外依赖 |
|---|---|---|
| `self-contained` | 推荐，普通用户直接运行 | WebView2 Runtime |
| `framework-dependent` | 已安装 .NET、希望包更小的用户 | .NET 8 Desktop Runtime x64、WebView2 Runtime |

Windows 11 通常已经包含 WebView2 Runtime；若 Web 插件无法打开，请从 Microsoft 官方渠道安装 Evergreen WebView2 Runtime。

## 2. 校验下载文件

将 ZIP 和 `SHA256SUMS.txt` 放在同一目录，在 PowerShell 中执行：

```powershell
Get-FileHash .\LongBetterWindows-v1.9.0-win-x64-self-contained.zip -Algorithm SHA256
```

输出哈希必须与 `SHA256SUMS.txt` 中对应文件完全一致。候选包当前未签名，Windows 可能显示未知发布者提示。

## 3. 安装与首次启动

1. 将 ZIP 解压到当前用户可写目录，例如：

   ```text
   %LOCALAPPDATA%\Programs\LongBetterWindows
   ```

2. 不要直接放入需要管理员写权限的 `Program Files`。当前便携版本会在应用目录保存插件、配置和日志。
3. 运行 `LongBetterWindows.Host.exe`。
4. 首次启动后确认托盘图标存在，并使用 `Alt + Space` 打开命令中心。
5. 如果 `Alt + Space` 已被其他软件占用，宿主会尝试 `Ctrl + Alt + Space`。

## 4. 数据位置

| 数据 | 默认位置 | 升级时处理 |
|---|---|---|
| 内置和第三方插件 | `<应用目录>\Plugins` | 保留第三方插件，更新内置插件 |
| 插件 Key-Value 数据 | `<应用目录>\config\storage.json` | 必须保留 |
| 日志 | `<应用目录>\logs` | 可删除 |
| 主题设置 | `%LOCALAPPDATA%\LongBetterWindows\theme.json` | 保留 |
| 文件夹备注 | 对应 NTFS 文件夹的 ADS 数据流 | 不随应用卸载自动删除 |
| 系统集成状态 | 当前用户注册表 | 卸载前在 ToolCenter 中关闭 |

## 5. 升级

1. 从托盘菜单彻底退出 Long窗口。
2. 备份 `<应用目录>\config` 和所有自行安装的第三方插件目录。
3. 校验新版本 ZIP 的 SHA-256。
4. 将新包解压到新目录，先复制原有 `config` 和第三方插件，再启动验证。
5. 验证命令中心、托盘、热键和常用插件后，再删除旧目录。

候选阶段推荐“新目录并行升级”，不要直接覆盖旧目录，以便快速回滚。

## 6. 回滚

1. 退出当前版本。
2. 启动升级前保留的旧目录中的 `LongBetterWindows.Host.exe`。
3. 如新版本写入过配置，可将备份的 `config` 恢复到旧目录。
4. 插件 Manifest 新字段均提供兼容默认值，但回滚前仍建议保留插件备份。

## 7. 卸载

1. 在 ToolCenter 的“系统集成”中关闭开机自启、Explorer 右键菜单和其他已启用集成。
2. 从托盘彻底退出应用。
3. 删除应用目录。
4. 如需删除主题设置，可删除 `%LOCALAPPDATA%\LongBetterWindows`。
5. 如需彻底清理当前用户注册表配置，可检查并删除 `HKCU\Software\LongBetterWindows`。

删除应用不会自动删除已经写入各文件夹 NTFS ADS 的备注数据。

## 8. 发布验收：干净 Windows 用户环境

正式发布前必须在新建 Windows 用户或一次性虚拟机中验收候选 ZIP。源码构建目录、长期使用的开发账户和只做进程冒烟都不能替代本门禁。

### 8.1 采集自动证据

进入仓库根目录，在候选包从未启动、Long窗口进程未运行时执行：

```powershell
.\capture-clean-environment-evidence.ps1 `
  -ReleaseZip .\artifacts\releases\v1.9.0\LongBetterWindows-v1.9.0-win-x64-self-contained.zip `
  -ReleaseManifest .\artifacts\releases\v1.9.0\release-manifest.json `
  -OutputDirectory .\artifacts\quality\clean-windows-v1.9.0 `
  -EnvironmentLabel "Windows 11 24H2 disposable VM" `
  -ConfirmCleanUserEnvironment
```

脚本会校验 Release Manifest 与 ZIP 哈希、解压真实候选包、检查 25 个唯一插件和 42 条命令，执行真实命令与完整桌面 UI/WebView2 冒烟，并把机器、用户 SID、系统版本和证据哈希写入清单。它不会自行断言账户“干净”，缺少 `-ConfirmCleanUserEnvironment` 时会直接拒绝。可以对未签名候选做预检并保留证据，但最终汇总只接受 Manifest 中 `signed=true` 且 `release_eligible=true` 的正式候选，因此签名后必须重新采集。

### 8.2 人工生命周期验收

自动采集结束后，由另一名验收者按第 3—7 节完成以下检查：首次启动、托盘图标、全局热键、WebView2 插件、新目录并行升级与数据保留、旧版本回滚、卸载及系统集成清理。批准脚本会拒绝使用采集账户名作为审核人。全部通过后执行：

```powershell
.\approve-clean-environment-evidence.ps1 `
  -EvidenceDirectory .\artifacts\quality\clean-windows-v1.9.0 `
  -Reviewer "reviewer-name" `
  -ReviewNotes "已在一次性虚拟机完成完整便携版生命周期验收" `
  -ConfirmFirstStart -ConfirmTrayIcon -ConfirmGlobalHotkey -ConfirmWebViewRuntime `
  -ConfirmParallelUpgradeDataPreserved -ConfirmRollbackToPreviousVersion `
  -ConfirmUninstallIntegrationsRemoved
```

最后汇总门禁：

```powershell
.\verify-clean-environment-evidence.ps1 `
  -EvidenceDirectory .\artifacts\quality\clean-windows-v1.9.0 `
  -OutputPath .\artifacts\quality\clean-windows-v1.9.0-summary.json
```

证据文件缺失、哈希被修改、自动检查失败、缺少人工批准或任一生命周期项目未确认时，门禁都会拒绝通过。
