# 插件人工证据验收

本文用于关闭 `docs/plugin-positive-function-matrix.json` 中 25 项真实桌面人工检查。自动测试、隔离宿主和机器探针不能代替人工确认；未经实际操作和逐份审阅，不得生成批准回执。

## 证据模型

- 原始截图、录像和机器报告保存在 `artifacts/quality/`，不提交 GitHub。
- 仓库只提交 `docs/plugin-manual-approvals/` 下的批准回执。
- 回执记录审阅人、说明、源码提交、插件 Manifest 哈希、受测 Release EXE 哈希、命令集合，以及每份原始证据的相对路径、大小和 SHA-256。
- 校验器不要求其他电脑持有原始大文件，但会复核回执的来源、范围和哈希元数据。
- 批准后只要 `src/` 发生变化、Manifest 或命令集合变化，旧回执即失效，必须重新验收。

## 执行步骤

1. 在干净提交上构建 Release：

   ```powershell
   dotnet build .\LongBetterWindows.sln -c Release
   ```

2. 按 [插件正向功能验收矩阵](插件正向功能验收矩阵_2026-07-27.md) 操作对应插件。高副作用检查只能使用可丢弃文件、临时监听进程和无害目标应用。
3. 将原始证据保存到本次专用目录，例如：

   ```text
   artifacts/quality/plugin-manual-9b6152f/
   ```

4. 逐份检查原图、录像和报告后创建批准回执。示例：

   ```powershell
   .\approve-plugin-manual-evidence.ps1 `
     -PluginId "com.long.window-manager" `
     -ManualCheckId "layouts-topmost-multimonitor" `
     -Reviewer "实际审阅人" `
     -Notes "已验证正常/最小化/最大化窗口、多显示器、置顶和高权限拒绝。" `
     -EvidenceFiles @(
       "artifacts/quality/plugin-manual-9b6152f/window-manager-report.json",
       "artifacts/quality/plugin-manual-9b6152f/window-manager-layout.png"
     ) `
     -ConfirmPassed
   ```

5. 检查生成的 JSON，只暂存批准回执，不暂存 `artifacts/`。
6. 运行聚合校验：

   ```powershell
   .\verify-plugin-positive-matrix.ps1 `
     -OutputPath "artifacts/quality/plugin-positive-matrix/report.json"
   ```

7. 仅当 25 项人工检查都存在有效回执，且跟踪工作区干净时，运行发布门禁：

   ```powershell
   .\verify-plugin-positive-matrix.ps1 -RequireReleaseEligible
   ```

## 修改与撤销

- 首次批准不得使用 `-Replace`；重新完整验收同一项且旧回执存在时才可使用 `-Replace`。
- 首次回执不可覆盖且原子创建；重审会锁定旧回执 SHA-256 并原子替换。目标变化或另一审核进程先提交时，本次重审会失败，不得通过再次并发运行覆盖其结论。
- 如果检查失败或证据不足，不生成回执，在审计文档中记录问题和复现条件。
- 发现误批时删除对应回执并提交该删除；原始证据仍按本地质量资料保留。
- 不要手工将矩阵基础状态改成 `passed`。校验器会把有效回执投影为当前提交的有效通过状态。

## 与其他人工门禁的边界

本流程只处理插件正向功能矩阵的 25 项检查。任务栏肉眼分组、物理 DPI、辅助功能/Narrator 和管理员 WPR 使用各自的采集与批准脚本，不能用插件回执替代。
