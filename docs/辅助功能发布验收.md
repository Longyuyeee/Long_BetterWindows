# Long助手辅助功能发布验收

> 目标：在真实 Windows 高对比度、关闭动画和 Narrator/NVDA 环境中生成可追溯的键盘与朗读证据。工程强制参数不能替代本流程。

## 1. 三种真实系统配置

分别准备以下配置，每次切换后按 Windows 要求注销或重启应用：

1. `high_contrast`：开启 Windows 高对比度，保持动画开启。
2. `reduced_motion`：关闭高对比度，在 Windows 中关闭动画效果。
3. `combined`：同时开启高对比度并关闭动画效果。

至少选择其中一组启动 Narrator 或 NVDA。采集脚本只读取系统状态，不会替测试人员修改设置；声明与实际状态不一致时会立即失败。

## 2. 采集自动证据

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\capture-accessibility-evidence.ps1 `
  -OutputDirectory .\artifacts\accessibility-physical-high-contrast-YYYYMMDD `
  -ExpectedProfile high_contrast `
  -ExpectedSourceCommit "完整的 40 位候选源码提交" `
  -ScreenReader Narrator
```

其余配置分别替换为 `reduced_motion` 和 `combined`。未使用读屏器的配置可传入 `-ScreenReader None`。脚本会执行完整桌面 UI 自动化，保存报告、日志、系统状态和 SHA-256。自动门禁同时要求真实 `SendInput` 方向键、搜索框 UIA 焦点事件和选中项 live-region 事件来自同一宿主进程；这只证明事件送达，不代表 Narrator/NVDA 已被真人听到。

## 3. 人工操作与批准

测试人员必须在同一配置下实际完成：

1. 仅使用键盘打开命令中心、搜索、上下移动、执行和关闭。
2. 打开二级操作菜单，在超级面板与命令中心间切换。
3. 打开插件市场、切换分类与版本、打开并取消确认层。
4. 管理中心概览不提供冗余自跳转；从首页依次按 `Tab`，确认焦点顺序为插件、插件市场、组合动作、桌面组件、系统集成、平台诊断、开发者、设置，再用 `Shift+Tab` 反向检查。
5. 分别用 `Enter` 和 `Space` 打开管理入口，关闭设置标签后回到管理中心；重新激活并关闭插件市场后仍回到管理中心，MRU 不跳到无关模块。
6. 检查每一步焦点轮廓清晰且顺序合理，没有键盘陷阱。
7. 检查关闭动画时没有不必要过渡，高对比度时文本、选中态和危险提示可辨认。
8. 使用 Narrator/NVDA 时确认窗口、搜索框、结果列表、按钮、状态变化和错误提示朗读准确，并听到“关闭设置”和“关闭插件市场”（英文界面对应 `Close Settings`、`Close Plugin Market`）。

随后批准对应证据：

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\approve-accessibility-evidence.ps1 `
  -EvidenceDirectory .\artifacts\accessibility-physical-high-contrast-YYYYMMDD `
  -ExpectedSourceCommit "完整的 40 位候选源码提交" `
  -ConfirmProfile high_contrast `
  -Reviewer "测试人员姓名" `
  -ReviewNotes "完成键盘、焦点、动效和 Narrator 朗读检查" `
  -ConfirmKeyboardNavigation `
  -ConfirmFocusVisibility `
  -ConfirmMotionBehavior `
  -ConfirmManagementTabOrder `
  -ConfirmManagementActivation `
  -ConfirmManagementModuleCloseMru `
  -ConfirmScreenReaderAnnouncements `
  -ConfirmManagementCloseAnnouncements
```

未使用读屏器的证据不要传入最后两个读屏确认参数；三个管理中心确认参数始终必填。

## 4. 汇总门禁

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\verify-accessibility-matrix.ps1 `
  -EvidenceDirectories `
    .\artifacts\accessibility-physical-high-contrast-YYYYMMDD, `
    .\artifacts\accessibility-physical-reduced-motion-YYYYMMDD, `
    .\artifacts\accessibility-physical-combined-YYYYMMDD `
  -ExpectedSourceCommit "完整的 40 位候选源码提交" `
  -OutputPath .\artifacts\quality\accessibility-release-matrix.json
```

采集要求仓库 `HEAD` 等于指定的完整提交 SHA、受跟踪文件无改动，并重新构建该提交；`-NoBuild` 不能用于正式物理证据。汇总只接受 v3 原始证据，要求三种唯一配置来自同一个指定提交、全部通过自动检查和管理中心专项人工签核、UIA 焦点/live-region 事件完整、证据哈希未变化，并至少包含一组 Narrator 或 NVDA 常规公告与管理模块关闭公告批准。汇总输出为 v4，并在摘要旁生成同名 `.sources` 目录；跨电脑复核必须同时携带两者。任一条件不满足时不允许标记正式 Release。
