## 最短执行顺序

### 1. 更新、聚合并冻结候选

```powershell
git checkout master
git pull --ff-only origin master
$candidate = (git rev-parse HEAD).Trim()
$evidence = "artifacts/quality/final-acceptance-$($candidate.Substring(0,7))"
.\verify-final-closure.ps1 `
  -OutputPath "$evidence/final-closure.json" `
  -RequireHumanValidationReady
.\package-long.ps1 -PackageKind All
.\plan-next-plugin-validation.ps1 `
  -OutputPath "$evidence/next-plugin.json"
.\start-plugin-validation.ps1 -PrepareOnly
```

只有 `machine_blockers=[]` 且 `ready_for_human_validation=true` 才继续。保留这一提交实际构建并受测的
Release EXE；规划器还必须通过 Manifest、ZIP 和解压 EXE 三重绑定。提交回执后不要用证据分支的新 `HEAD`
重建并替换它。

### 2. 完成 25 个插件回执

按照 [用户最终验收操作手册](用户最终验收操作手册.md) 和
[`plugin-manual-approvals/README.md`](plugin-manual-approvals/README.md) 操作。每次批准前跟踪工作区必须干净，
生成一份回执后只提交该 JSON，再继续下一份。随时检查：

```powershell
.\start-plugin-validation.ps1
```

脚本会自动选择下一项、创建不可混用的本地证据会话并启动冻结 EXE；它不会自动批准。目标是
`approval_receipt_count=25`、`pending_manual_check_count=0`、
`complete=true`；随后再以 `verify-plugin-positive-matrix.ps1 -RequireReleaseEligible` 关闭矩阵门禁。

实际观察并逐份检查会话目录内的截图/录像后，使用 `complete-plugin-validation.ps1` 输入审核人、说明、证据路径
和 `-ConfirmPassed`。该入口自动绑定当前会话与冻结 EXE，返回 `receipt_created_pending_commit` 后只提交对应
`docs/plugin-manual-approvals/*.json`，再开始下一项。失败或证据不足时不得运行完成入口。

### 3. 完成五类最终产品批准

完整命令见 [最终产品验收门禁](最终产品验收门禁.md)。五次调用始终传入步骤 1 的同一个 `$candidate`：

```powershell
.\approve-final-validation-evidence.ps1 `
  -ValidationId <五个精确ID之一> `
  -ExpectedSourceCommit $candidate `
  -Reviewer "<审核人>" -Notes "<观察结论>" `
  -EvidenceFiles <摘要和全部原始证据> `
  -SubjectExecutable "<冻结候选的LongBetterWindows.Host.exe>" `
  -ConfirmPassed
```

Long Grid 先使用 `new-lpwp-long-grid-e2e-evidence.ps1` 生成双提交、六方法和原始证据哈希摘要；操作者与
批准人必须不同。签名参考包必须使用独立保存的正式 Publisher Key ID 和公钥指纹，不能使用应用自动更新密钥。

每份最终批准回执也单独提交。候选之后除两个批准目录中的 JSON 外出现任何变化，脚本都会要求重新冻结候选。

### 4. 生成最终产品验收摘要

```powershell
.\verify-final-product-acceptance.ps1 `
  -ExpectedSourceCommit $candidate `
  -SubjectExecutable "<冻结候选的LongBetterWindows.Host.exe>" `
  -OutputPath "$evidence/product-acceptance.json"
```

摘要和 `product-acceptance.sources/` 必须一起保存、传输和复核。

### 5. 完成发布环境门禁

按 [安装升级与卸载](安装升级与卸载.md) 完成真实下载、干净 Windows、物理 DPI、辅助功能与生产
Marketplace 演练，然后把各门禁摘要和 `.sources/` 一起传给 `verify-external-release-gate.ps1`。只有统一
决策输出 `passed=true` 后，才允许创建正式稳定 Release。
