# .NET 原生插件专用能力边界实施审计（PX3D-B）

> 日期：2026-07-30
> 状态：工程完成，待真实桌面抽查
> 基线：PX3D-A 后 3 个原生插件直接引用 Host

## 目标与结论

本批为屏幕像素采样建立可授权、可替换测试的宿主能力，并在 WPF UI Kit 中提供公开的锚点文本编辑 Surface。ColorPicker 与 FolderNote 已移除 Host 项目引用，直接宿主耦合由 **3 个降为 1 个**。

当前唯一剩余项目为 `QuickLaunchPlugin`，依赖宿主搜索 DTO 与 `ISearchProvider`，将在 PX3D-C 迁移。

## 屏幕颜色采样合同

新增 `IScreenColorSampler` 和不可变 `ScreenColorSample`：

- 输入使用物理桌面坐标，避免 DPI 缩放后采样偏移；
- 输出为 RGB 数据和稳定 Hex 投影，不向插件暴露 GDI 句柄；
- Win32 失败转换为 `HostApiResponse` 与 `ApiErrorCode.Win32Error`；
- 能力映射复用 `system.screenshot`，不增加语义重复的 Manifest 权限；
- 生产 Host 与 `PluginTestHost` 使用同一份 `HostCapabilityCatalog` 映射。

ColorPicker 只依赖 `IScreenColorSampler`、Clipboard、Notification、HotKey 和 Plugin Settings。采样实现、GDI 资源释放与权限判断继续由 Host 持有。

## 锚点文本编辑 Surface

`LongBetterWindows.PluginSdk.Wpf` 新增 `AnchoredTextEditorWindow`：

- 显式接收位置、初始文本、上下文标签、保存回调与本地化模型；
- `Ctrl+Enter` 保存、`Esc` 取消，失焦三秒后延迟保存；
- 保存失败留在当前 Surface，并以语义危险色显示错误；
- 遵循 `Long.Motion.*`、`LongToast` 和 `Long.Brush.*` 动态资源；
- 关闭时取消延迟任务，不在插件停用后继续投递保存。

FolderNote 保留 ADS 与 Explorer 业务合同，但不再使用 Host 的 `FloatingHudWindow`。普通读取/路径错误通过 `INotificationService` 呈现。

## 边界审计

SDK-only 原生项目现为：

- ClipboardHistoryBackground
- ColorPickerPlugin
- FolderNotePlugin
- MacroPlugin
- SamplePlugin
- ScreenshotPlugin
- WindowManagerPlugin

`native-plugin-boundary-audit.json` 与实际 `.csproj` 交叉门禁确保清单不会提前宣称迁移完成。

## 自动化门禁

- `IHostApi` 每个服务入口必须存在唯一服务类型映射；
- `IScreenColorSampler` 必须由 Contracts SDK 持有并映射到 `system.screenshot`；
- ColorPicker、FolderNote 的编译产物不得引用 Host；
- 真实 GDI 采样继续验证成功响应和 Hex 格式；
- 锚点编辑 Surface 的异步保存、异常保留和生命周期结构继续由回归测试覆盖；
- 全量 Manifest 继续通过生产读取器和 Draft 2020-12 Schema。

最终验证结果：ColorPicker、FolderNote 构建发布目录均通过生产验证；WPF UI Kit v1.0.0 NuGet 结构通过；四运行时生产验证/确定性打包矩阵 4 / 4；全量自动化 975 / 975；Release 解决方案构建 0 警告、0 错误。

## 后续顺序

2. 当机器清单 `host_coupled_projects` 为空后，执行 PX3D 总体边界审计并转入插件开发体验收口。
