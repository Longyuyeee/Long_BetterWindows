## 机器门禁

运行普通契约检查：

```powershell
.\verify-plugin-positive-matrix.ps1 `
  -MatrixPath docs/plugin-positive-function-matrix.json `
  -SourceRoot src `
  -OutputPath artifacts/quality/plugin-positive-matrix/report.json
```

校验器会拒绝：

1. 正式插件不再是 25 个或命令不再是 42 条；
2. Manifest 与矩阵的插件 ID、命令或运行时类型不一致；
3. 自动证据文件或测试符号已删除、改名；
4. 任一命令没有对应的人工正向检查；
5. 重复插件、重复人工检查、非法状态；
6. 人工检查标记为 `passed`，但证据文件不存在、SHA-256 缺失或不匹配。

发布前必须额外使用：

```powershell
.\verify-plugin-positive-matrix.ps1 -RequireReleaseEligible
```

只要存在 `pending`、`blocked`、`failed`，或有已跟踪源码修改未提交，命令就以退出码 `2` 阻止候选发布。

低风险真实命令矩阵：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\verify-low-risk-plugin-commands.ps1 `
  -OutputPath artifacts/quality/low-risk-plugin-commands/report.json
```

该门禁逐案例启动新的 Release 宿主，只向临时插件根复制目标插件，并验证结果、错误传播、输入 SHA-256、输出和宿主 API 白名单。聚合报告只保存输出长度与哈希，不保存随机密码、UUID 或原始输入。


每个案例同时安装进程内剪贴板、存储和 HTTP 夹具。夹具状态及调用账本进入临时命令报告，聚合证据只保留长度、哈希与计数；任何访问未列入白名单的方法都会失败。

该门禁只在系统随机临时工作区生成文件和目录，并为每个案例对比执行前后完整文件树指纹。PortManager 只查询矩阵进程持有的随机 TCP 监听端口。命令自动化只生成文件整理/重命名预览、读取 FolderNote 空备注和查询端口，不绕过确认按钮执行文件修改、ADS 写入或进程终止；真实写入的预检、拒绝和回滚由事务服务测试覆盖。

## 人工执行顺序

### A. 低风险纯工具

先执行 Base64、JSON、Markdown、密码、正则、Sample、文本对比、时间戳、URL 和 UUID。使用固定中英文输入，验证结果、错误态、复制和语言切换。HardwareMonitor 只读取指标，但需确认刷新和窗口生命周期。

### B. 中风险状态与网络

依次验证 ClipboardHistory、ClipboardTool、DevToolkit、QuickNote、Translate。必须使用测试数据；Translate 同时验证联网成功、断网失败提示和恢复。

### C. 高风险隔离目标

FileOrganizer、FileRenamer、FolderNote 只允许操作新建临时目录；PortManager 只允许终止本轮启动的临时监听进程。ColorPicker、Screenshot 验证真实 Overlay 和系统剪贴板；QuickLaunch 使用可删除的大目录样本并只启动无害目标。

代码与受控边界预检统一运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\verify-high-risk-plugin-boundaries.ps1
```

该入口覆盖 7 个高风险插件和 43 个受控案例，但不代替 Overlay、真实系统剪贴板、跨屏 DPI 和主观交互流畅度人工确认。

Screenshot 的自动边界已统一到 Win32 物理虚拟屏幕，并显式验证选择器焦点；人工检查时仍需观察遮罩是否完整覆盖每台显示器、尺寸标签是否跟手，以及 Esc 后旧剪贴板是否保持不变。

### D. 关键桌面副作用

最后验证 WindowManager 与 Macro。WindowManager 覆盖正常、最小化、最大化、多显示器、置顶和高权限拒绝；Macro 只在可丢弃目标中录制，覆盖单次播放、循环停止和取消后无残留按键/鼠标按钮。

代码预审已补齐 Macro 停止后重启引擎恢复，以及命令面板执行前归还原前台窗口；桌面副作用生命周期门禁为 12 / 12。接手后仍按“焦点返回、窗口布局与置顶回滚、宏播放与取消清理”的顺序做真实桌面检查，未签核前不要修改人工状态。

Macro `1.1.3` 已保留组合键的 KeyDown/KeyUp 顺序、修正动作前延迟并剔除停止热键；默认 F6/F7/F8 可直接注册。生命周期门禁 15 / 15、全量自动化 992 / 992 通过，人工检查需增加 `Ctrl+C` 等组合键回放，状态仍保持 pending。

Macro `1.1.4` 进一步保留左右鼠标键的 MouseDown/MouseUp、按住时长和释放坐标，旧 `MouseClick` JSON 保持兼容；拖拽中途取消会补发对应 MouseUp。桌面副作用门禁 18 / 18、全量自动化 995 / 995 通过；人工签核必须覆盖左键拖拽、右键动作及拖拽期间取消，不能用普通点击代替。

## 证据回写规则

每个通过项需要在干净提交上实际操作并逐份审阅证据，再运行 `approve-plugin-manual-evidence.ps1`。原始机器报告、截图和录像保存在 `artifacts/quality/` 且不提交；脚本将审阅人、说明、源码提交、Manifest/Release EXE 哈希、命令集合和原始证据哈希写入 `docs/plugin-manual-approvals/` 的可移植回执。仓库只提交回执，不手工修改矩阵基础状态。

普通校验器会将有效回执投影为当前提交的 `passed`；`src/`、Manifest 或命令集合在批准后发生变化时，回执自动失效。全部人工项都有有效回执后，再运行 `-RequireReleaseEligible`。完整命令与撤销规则见 [插件人工证据验收](插件人工证据验收.md)。

禁止只凭口头结论、聊天截图或测试日志摘要标记通过。自动组件测试仍保留原来的层级：`contract` 证明协议存在，`component` 证明隔离组件行为，`integration` 证明真实宿主边界；它们都不能替代最终人工桌面正向检查。
