## 1. 结论

Long助手没有偏离最初目标：继续采用 Long 自有的优雅、华丽、扁平化和动效化视觉，以 uTools 作为统一唤起、上下文匹配、超级面板、插件承载和市场交互的逻辑参考，不实施 uTools 插件兼容层，也不复制其品牌、素材或界面细节。

当前不能宣称与 uTools 完全对齐。Long助手已经形成更系统的 Workspace、组合动作、能力授权、生命周期治理、可信市场、开发者工具和可访问性证据；uTools 仍在内容匹配表达力、动态指令、插件结果回推、图片/文件即时处理、插件生态广度和轻量入口扫描效率上领先。

该差距不应扩大 v1.11.0 稳定版范围。v1.11.0 继续完成 RC15 安装与人工门禁；本审计识别的产品扩展全部进入 v1.12 或更晚版本。

## 4. UI 与交互审计

### 4.1 主搜索入口

uTools 默认态不是普通结果列表，而是“最近使用、已固定、市场精选”的图标分区；查询态切换为“最佳搜索结果、匹配推荐”，首项具有明显选中态，命中关键词局部着色，窗口高度会随结果数量变化。

Long助手已经具备最近、固定、使用频率、结果来源、描述、次级动作和键盘帮助，但 Command Palette 更偏高密度纵向列表。后续应吸收信息架构，而不是复制大面积白底和超大图标：

1. 空查询态增加紧凑的最近/固定视觉入口；
2. 查询态明确区分最佳匹配、上下文推荐和普通结果；
3. 增加统一插件图标和 Long 主题色关键词强调；
4. 结果较少时允许窗口平滑收缩，仍满足 DPI、减少动效和焦点稳定要求；
5. 保持 Command Palette 的键盘密度，让 Super Panel 承担更图标化的鼠标入口。

### 4.2 上下文与超级面板

uTools 可以对文本、图片、文件、文件夹和活动窗口进行声明式匹配；超级面板支持拖拽排序、图标合并文件夹、滚轮分页、移除、重命名和语音输入。

Long助手已经完成文本、URL、图片、文件、文件集合、空上下文采集，具备固定/最近分组、拖拽排序、入口连续性、组合动作和 Workspace 返回。但正式插件没有消费全部平台能力，且缺少活动窗口规则、图标文件夹和语音入口。

### 4.3 插件承载与返回

uTools 插件可接管主窗口、隐藏主搜索入口、转为独立 BrowserWindow，Esc 后默认可在后台驻留。Long助手已经通过 Embedded、Detached、Workspace 模块页签、后台/混合生命周期和返回来源保存形成更明确的状态模型。

后续重点不是复刻 uTools 窗口，而是继续简化 Long 的“打开—分离—返回—关闭—后台驻留”状态提示，并保证不同承载模式的查询、上下文、焦点和任务栏身份连续。

### 4.4 可访问性

本机 uTools 7.5.1 的主搜索窗口在当前配置下仅向 Windows UI Automation 暴露 `Chrome Legacy Window`，不能从该样本获取细粒度控件语义。该观察不能推导所有 uTools 环境均不可访问，但说明 Long助手现有按钮名称、AutomationId、焦点恢复、高对比度和减少动效证据应继续作为差异化优势，不能为了视觉模仿而退化。

## 5. 平台与插件对比

| 能力 | uTools 7.5.1 / 官方契约 | Long助手当前 | 判定 |
|---|---|---|---|
| 全局唤起与统一搜索 | 完整 | 完整 | 对齐 |
| 最近与固定 | 搜索面板/超级面板 | 搜索偏好、固定、最近、排序 | 对齐 |
| 静态指令 | 支持 | 42 条 Manifest 命令 | 对齐 |
| 动态指令 | 运行时增删 | 无公开运行时增删契约 | 缺口 |
| 文本匹配 | `regex` / `over` | 宽类型 `text/url/clipboard` | 部分对齐 |
| 图片匹配 | `img` | 平台支持 `Image`，正式命令使用数为 0 | 明确缺口 |
| 文件匹配 | 类型、扩展名、数量、正则 | `file/files/folder/explorer_selection` | 部分对齐 |
| 活动窗口匹配 | 应用、标题、窗口类 | WindowManager 能力存在，无声明式匹配 | 缺口 |
| 插件结果回推 | 主搜索面板推送 | DLL `IPluginSearchProvider`，Web 动态回推不足 | 部分对齐 |
| 插件承载 | 主窗、独立窗、后台 | Workspace、嵌入、分离、后台/混合 | Long 更完整 |
| 市场生态 | 评分、评论、版本、发布者 | 可信本地市场与事务已完成，生产生态延期 | 外部依赖缺口 |
| 工作流 | 以独立插件功能为主 | 组合动作、补偿、审核、参数 Schema | Long 优势 |
| 能力治理 | API 与平台权限 | 27+ 能力、授权、调用审计 | Long 优势 |
| 可访问性证据 | 本机样本语义有限 | UIA、键盘、焦点、辅助模式 | Long 优势 |

Long助手的 25 个正式插件、42 条命令共声明 71 个输入类型：`none` 29、`text` 17、`clipboard` 15、`url` 3、`explorer_selection` 3、`folder` 2、`file` 1、`files` 1、`image` 0。平台并非不支持图片，而是正式插件覆盖没有落地。

## 6. 不得照搬的边界

1. 不复制 uTools 名称、图标、页面布局、素材、文案或插件包。
2. 不实现 uTools 插件兼容层；Long 使用 LPWP、Manifest、SDK 和能力授权边界。
3. 不把 Long 的工作区改成单一 Electron 插件窗口；保留 Windows 原生 WPF 宿主和统一 Workspace。
4. 不因追求大图标宫格而牺牲高密度键盘效率、UIA 语义和多 DPI 稳定性。
5. 不把缓存索引数量当作市场生态完成，也不在没有 Registry/CDN/发布者身份时伪造评论评分。
6. v1.11.0 不新增高风险协议和插件，只修复人工验收发现的稳定性阻断。

## 7. 后续严格路线

### v1.11.0：稳定版收口

1. RC15 桌面自动化探索已经通过并合入 `cee1ae0`；
2. 完成本机当前用户安装、首次启动、升级/卸载和残留检查；
3. 完成人工视觉、键盘、任务栏、托盘和真实读屏签核；
4. 完成 25 / 25 插件人工回执；
5. 在 Windows Sandbox、VM 或新本地用户中完成可获得的最高强度隔离验证；
6. 所有门禁通过后重新冻结正式 `1.11.0`，不得把 RC15 文件直接改名为稳定版。

### v1.12-P1：声明式上下文匹配

为 Long Manifest 增加可审计、可限额的匹配声明：

- 文本 `regex` / `over`，带最小/最大长度和正则超时；
- 图片 `image`；
- 文件/文件夹类型、扩展名、数量和安全名称匹配；
- 活动窗口的进程、标题和类名规则；
- 旧 `accepted_inputs` 完全向后兼容；
- 匹配失败、超时或无权限时不得影响主搜索响应。

验收目标：契约、解析器、验证器、SDK、Web SDK、搜索排序、权限边界、回归测试和开发文档同时落盘；恶意或灾难性正则不能阻塞 UI。

### v1.12-P2：动态指令与结果回推

- 支持插件运行时注册、更新和撤销指令；
- 插件停止、崩溃、卸载或热重载时原子清理动态入口；
- Web 插件可在限额、取消和能力授权下向搜索面板推送结构化结果；
- 动态结果复用固定、最近、排序、次级动作和审计系统；
- 禁止插件绕过 Manifest 身份或伪造其他插件结果。

### v1.12-P3：首批上下文插件

按本地优先和 Windows 场景选择，而不是追求插件数量：

1. 图片工具：图片上下文打开、尺寸/格式/压缩/裁剪基础能力；
2. 二维码工具：文本生成与图片识别；
3. 文档工具：PDF 合并、拆分、转图片等可离线能力；
4. 增强本地搜索：优先 Windows Search，可选受控 Everything 适配器；
5. OCR 作为独立里程碑评估本地模型体积、许可、隐私和性能后再决定。

每个新插件都必须完成双语、Manifest、能力最小化、命令输入输出、错误/空态、键盘、DPI、减少动效、生命周期、内存和人工回执。

### v1.12-P4：入口 UI 精修

- 空查询最近/固定紧凑区；
- 最佳匹配与上下文推荐分区；
- 统一图标、关键词强调、结果来源和风险状态；
- 自适应高度与减少动效降级；
- Super Panel 文件夹与分页先设计协议，再实现拖拽和键盘等价路径。

### v1.13 或更晚

语音输入、生产市场社区、跨设备同步、AI Provider 和复杂在线服务需要独立隐私、账号、成本、网络和发布政策，不进入 v1.12 的基础对齐门禁。

## 8. 收口判定

Long助手目前应判定为：**核心交互逻辑与 uTools 参考方向对齐，平台治理和工作区能力具有自身优势；内容匹配表达力、图片插件覆盖、动态指令和生态广度尚未完全对齐。**

近期唯一正确动作仍是关闭 v1.11.0 人工与隔离门禁；v1.12 按 P1→P2→P3→P4 顺序补齐差距，每个阶段继续采用审计、文档、独立提交、PR、CI 和主分支复核闭环。
