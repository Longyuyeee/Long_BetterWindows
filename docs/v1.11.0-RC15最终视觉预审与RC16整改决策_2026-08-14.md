## 1. 结论

RC15 的管理中心、插件市场、开发者资源、设置、Command Palette、超级面板和 Web 插件在亮/暗主题与物理 250% DPI 下均能稳定渲染，没有发现裁切、文字重叠、模糊缩放、主题错色或退出残留。整体设计继续符合 Long 自有的扁平化、圆角卡片、渐变强调色和高密度键盘交互方向。

但 RC15 不能作为最终稳定版冻结：Command Palette 与超级面板中的绝大多数插件命令在没有图标文件时统一显示同一个十字形 `Long.Icon.Plugin` 占位图标，导致不同插件缺乏视觉身份。该问题在高频入口连续重复，既削弱扫描效率，也使完成度明显低于插件市场已经采用的中文首字徽标，更未达到 uTools 最近/固定/推荐入口以图标快速辨识的交互参考。

该问题属于已有功能的视觉收口缺陷，不是新增产品功能。决定提升到 RC16，以最小改动为无图片插件增加稳定首字徽标回退；RC15 资产继续不可变保留，不覆盖、不改名。

## 4. 阻断项：插件图标身份退化

### 现象

无独立图片图标的插件命令统一使用 `Long.Icon.Plugin`。该几何图形在 34×34 与 42×42 容器内近似紫色加号。Command Palette 一屏出现多个完全相同图标，超级面板的卡片也无法通过图形快速区分。

### 根因

- `SearchResultItem` 已支持 `IconPath`；
- `StaticCommandSearchProvider` 和 Workspace 搜索已经尝试解析插件图标；
- 25 个正式插件目前没有普遍提供可解析图片图标；
- Command Palette 和超级面板对 `IconKind=Plugin` 且 `IconPath` 为空时只显示统一路径图标；
- 插件市场已经有首字徽标回退，但两个高频入口没有复用这一视觉语言。

### 为什么阻断稳定版

最初目标不是复制 uTools 外观，而是参考其统一唤起、最近/固定/推荐和插件快速辨识逻辑，并保持 Long 自有的优雅、华丽、扁平化和动效化设计。高频入口的重复占位符同时损害“快速辨识”和“完成质感”，属于可在小范围、低风险内修复的视觉缺陷，不应带入稳定版。

## 5. RC16 最小整改范围

1. 为搜索结果增加只读的插件首字徽标投影；优先使用插件来源名称，来源缺失时回退命令标题；
2. 使用 Unicode 文本元素而不是单个 UTF-16 `char`，避免拆断代理对或组合字符；拉丁字母统一大写；
3. 仅当 `IconKind=Plugin` 且 `IconPath` 为空时显示首字徽标；真实插件图片图标始终优先；
4. Command Palette 与超级面板复用同一字段和相同显隐条件；
5. 管理中心、市场、设置、文件、文件夹、工作流等非插件图标不改变；
6. 徽标是装饰性补充，不改变结果项已有的 AutomationName、AutomationId、焦点或键盘行为；
7. 增加中文、拉丁文、Unicode 文本元素、真实图片优先和非插件结果回归测试；
8. 重新采集亮/暗 250% DPI 的 Command Palette 与超级面板截图，并运行 1461+ 全量测试、桌面 UI 自动化和安装器门禁；
9. 因为涉及产品代码/XAML，版本必须提升为新的 RC16，重新生成候选资产和哈希。

## 6. 不进入 RC16 的项目

以下项目继续属于 v1.12，不借视觉修复扩大稳定版范围：

- 把 Command Palette 空查询态改成 uTools 式大图标宫格；
- 声明式正则、文件、图片和活动窗口匹配；
- 动态指令与 Web 插件结果回推；
- 插件文件夹、语音输入、生产市场社区和 uTools 插件兼容层；
- 为 25 个插件逐个创作完整品牌图标资产。

首字徽标是稳定、可访问且可长期保留的缺省回退；插件未来提供真实图标后会自然替换，不造成协议债务。
