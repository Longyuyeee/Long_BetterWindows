# Long_BetterWindows 设计文档 (Part 1: 核心愿景与架构概览)

## 1. 项目愿景 (Project Vision)
打造一个极致优雅、深度集成的 Windows 效率增强中枢。它不仅是一个工具集，而是一个运行在原生系统之上的“轻量级桌面环境”，通过苹果风的视觉语言（Glassmorphism）和高度可扩展的插件机制，解决 Windows 原生功能滞后或难以使用的痛点。

## 2. 设计哲学 (Design Philosophy)
*   **无感集成 (Seamless Integration)：** 插件功能应像原生系统自带的一样自然（如备注助手的右键集成）。
*   **极致美感 (Aesthetic Excellence)：** 遵循 Apple 设计规范，采用毛玻璃（Acrylic/Mica）、大圆角、弹性动效。
*   **能力开放 (Capability Driven)：** 主程序不涉及具体业务逻辑，仅作为“能力供货商”，通过标准 API 驱动插件。
*   **离线安全 (Offline First)：** 核心流程不依赖网络，保证数据的私密性与极速响应。

## 3. 技术架构分层 (Layered Architecture)

系统采用 **“宿主-插件-原子能力”** 三层模型：

### A. 宿主层 (The Host Shell)
*   **职责：** 渲染虚拟桌面、管理插件生命周期、路由 API 请求。
*   **核心模块：**
    *   `WindowManager`: 处理毛玻璃窗口、Dock 栏及插件容器。
    *   `PluginEngine`: 负责 `.lpak` 包的解压、Manifest 校验、动态加载。
    *   `APIRouter`: 接收插件的 API 调用请求，并分发给对应的系统服务。

### B. 能力层 (Capability Service Layer)
*   **职责：** 封装高权限或复杂系统操作，向插件开放。
*   **首批开放能力：**
    *   `HotKeyService`: 全局热键注册与冲突检测。
    *   `ShellService`: 右键菜单(Context Menu)注册、文件路径感知。
    *   `RegistryService`: 安全的注册表读写接口（带回滚机制）。
    *   `StorageService`: 结构化 Key-Value 本地配置存储。

### C. 插件层 (Plugin Application Layer)
*   **职责：** 具体业务逻辑实现（如：文件夹备注、文件分类等）。
*   **形式：** 独立目录或压缩包，包含 UI 定义 (XAML/Web) 和 业务逻辑 (DLL/Script)。

## 4. 关于《基础能力 API 手册》的维护机制

为了确保随着插件开发，API 能够有序扩展，我们将建立以下机制：

1.  **API 版本化：** 每个接口都有版本号（v1, v2...），确保主程序升级后，老插件依然兼容。
2.  **契约优先：** 每次新增能力，必须先定义 **接口协议（Interface Contract）**，明确输入参数、返回类型及权限要求。
3.  **双向维护：** 
    *   **设计文档：** 记录“为什么需要这个能力”以及“设计思路”。
    *   **API 文档：** 记录“如何调用”及“错误代码”。

---

## 5. 本阶段关键备注
> **备注：** 宿主程序必须以“高权限管理模式”运行，以便统一代理所有插件的系统修改行为。主程序将作为一个 **Privilege Guard (权限卫士)**，所有插件对注册表的修改必须经过主程序的 `RegistryService` 接口，这允许用户在主程序设置中一键撤销所有插件做的系统修改。
