## 结论

RC15 已通过完整桌面 UI 自动化探索验收，最终报告记录 `passed=true`、`error=null`，运行耗时约 145 秒，退出后没有残留 `LongBetterWindows.Host.exe` 进程。候选应用本身没有在本轮发现新的阻断缺陷，可以继续进入安装、首次启动、人工视觉/辅助技术和 25 个插件的正式人工签核。

本轮同时发现并修复了桌面验收脚本的两个可靠性问题：

1. WPF 关闭按钮销毁或切换 UIA 提供者时，同步 `InvokePattern.Invoke()` 可能令验收进程永久等待；改为先验证按钮可发现、可聚焦，再通过 Space 触发真实按钮事件。
2. 待确认元素已经消失时，脚本曾退化为扫描整个 Windows 桌面的 UIA 树；无关应用的 UIA 提供者可能阻塞全局搜索。现在只搜索受测进程自己的顶层窗口树。

这些改动只影响仓库外部验收工具，不修改 RC15 候选程序或其已冻结资产，因此 RC15 的候选源码、ZIP、安装器和哈希保持不变。

PR 首轮 CI 暴露出一项配套质量门禁仍在强制要求旧的 `RootElement.FindFirst(... Descendants)` 全桌面扫描。该断言已改为验证顶层窗口的 `Children` 回退、候选进程限定搜索、禁止进程元素查找退回桌面根节点，以及键盘触发关闭入口。修复后针对性测试 1 / 1、全量测试 1461 / 1461 通过；这属于测试契约同步，不改变产品行为。

## 需求对齐判定

- 统一唤起、上下文搜索、Super Panel、Workspace 与插件化交互继续对齐最初的 uTools 交互逻辑参考边界。
- 本轮没有引入 uTools 插件兼容层，也没有改变 Long 自有视觉与产品身份。
- 键盘访问、焦点恢复、减少动效和高对比度均有自动化证据，符合优雅、扁平化、动效化同时兼顾可访问性的原始要求。
- 当前仍不能宣称稳定版完全收口：自动化桌面探索不能替代人工视觉质量、真实读屏、安装/升级/卸载、SmartScreen 观察和 25 / 25 插件人工回执。
