# v1.11.0 S1A 退出可观测性开发审计

> 日期：2026-08-13
> 阶段：S1A 结构化退出可观测性
> 状态：代码与自动化验收完成；真实宿主清理验收待关闭当前安装版后执行

## 1. 本批目标

本批只处理稳定版总计划的 S1A，不提前进入 S1B 的插件整体退出预算，也不修改 UI、版本号或发布候选。目标是让宿主退出能够回答：执行了哪些步骤、每步耗时、是否失败或超时、超时任务后来成功还是失败，以及证据是否绑定本次源码和宿主二进制。

## 2. 实现结果

1. `BestEffortShutdownSequence` 现在返回全部步骤结果，不再只返回失败列表。
2. 每项结果包含名称、`passed` / `failed` / `timed_out` 状态、耗时、超时预算和稳定错误分类。
3. 超时任务保留独立迟到完成任务；最终成功或失败会写入结构化日志，不改变原始超时决策。公开 JSON 若写入时已经观察到迟到结果则记录最终状态，否则如实记录 `pending`，不写入异常正文。
4. 宿主退出固定产生 `broker`、`plugins`、`plugin_runtime`、`host_services` 四个顶层步骤；组件未启动时执行安全空操作，因此证据集合不随启动路径漂移。
5. 新增 `--quality-shutdown-report` 和 `--quality-source-commit` 参数。报告通过 `FileMode.CreateNew` 创建，拒绝覆盖已有证据。
6. shutdown JSON 绑定源码提交、宿主路径和 SHA-256、PID、退出码及全部步骤结果。
7. `verify-host-process-cleanup.ps1` 升级到 Schema 3，必须读取并核对 shutdown JSON、四步骤顺序、成功状态、错误分类、提交、EXE 哈希、PID 和退出码。
