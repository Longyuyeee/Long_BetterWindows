# 开发审计：开发者页面懒加载

> 日期：2026-07-27
> 主线：`master`
> 目标：继续降低 Tool Center 默认启动视觉树成本，同时保持主题、响应式布局和插件生命周期契约。

## 本批结论

开发者工作区已从 `ToolCenterControl` 的内联隐藏面板迁移为独立
`DeveloperPageControl`，仅在首次进入“开发者”导航时创建。主窗口启动时不再构造
工作台、设计系统、开发文档和关于信息四张卡。

- `ToolCenterControl.xaml.cs` 净减少 81 行，开发者页面拥有自己的文档、关于信息、
  响应式布局和事件生命周期。
- 页面缓存到 Tool Center 卸载；卸载时解除插件与语言事件订阅并释放宿主引用。
- 文档列表限制为 240 逻辑像素高并独立滚动，避免文档数量拉高整个页面。
- 新增 `developer` 质量视图，可通过参数精确打开，不依赖鼠标坐标自动化。
- 结构门禁禁止在主 XAML 静态实例化开发者页，并检查四张卡、懒加载语句和事件释放。

## 审计证据

- Release 构建：0 警告、0 错误。
- 全量自动化：691 / 691 通过。
- 默认启动管理卡视觉树：21 张降为 17 张，减少的 4 张与开发者页卡片完全对应。
- 4 次当前实现启动采样中位数：主窗口 Loaded 1494.95 ms、插件运行时就绪
  2325.8 ms、私有内存 140.05 MB、工作集 184.15 MB。
- 本批只保留了 1 次迁移前同机样本，因此不对启动时间或内存声明因果降幅；
  确定收益以视觉树计数和所有权边界为准。
- 浅色 `1440×900` 双列与深色 `800×700` 单列截图均通过人工审阅：
  四张卡可达，文字无截断或遮挡，主次按钮对比正常，主题资源即时生效。

原始报告、截图及渲染元数据位于
`artifacts/quality/developer-page-lazy-20260727/`。

## 风险与后续方向

性能 P0 仍未关闭。当前启动工作集存在系统负载波动，不能仅凭一次优化生成新 RC。
后续按页面事务边界继续推进：

1. 将“系统集成”内联面板迁为首次导航创建的独立视图，保留注册表、启动项与
   Sparse Package 的异步初始化和取消边界。
2. 对系统页执行宽窄、明暗主题、状态刷新、导航往返和默认视觉树计数审计。
3. 将“设置”面板迁为独立视图，重点处理更新服务、语言切换、手势设置和卸载释放。
4. 三个页面迁移完成后，重新执行同二进制交错性能矩阵和 9 秒空闲内存门禁，
   再判断性能 P0 是否具备关闭条件。

本批方向与最初“宿主只负责导航和协调、功能由独立模块拥有”的分层设计一致，
没有改变插件能力注册、首次调用激活或 unsigned 发布策略。
