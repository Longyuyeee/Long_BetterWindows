# .NET 原生插件 WPF 边界实施审计（PX3D-A）

> 日期：2026-07-30
> 状态：工程完成，待真实桌面抽查
> 基线：PX3C 后 6 个原生插件直接引用 Host

## 目标与结论

本批建立可独立引用和打包的 `LongBetterWindows.PluginSdk.Wpf` v1.0.0，抽出共享热键设置控件与多显示器定位工具；同时把异步投递边界移入稳定 Contracts SDK 的 Core 编译边界，并用 `INotificationService` 替代普通 HUD Toast。

直接引用 `LongBetterWindows.Host.csproj` 的内置原生插件由 **6 个降为 3 个**：

- 已完全解耦：`MacroPlugin`、`ScreenshotPlugin`、`WindowManagerPlugin`；
- 仍保留专用依赖：`ColorPickerPlugin`（屏幕像素采样、旧 HUD）、`FolderNotePlugin`（锚点备注编辑浮层）、`QuickLaunchPlugin`（宿主搜索合同）。

## 关键设计决定

### 显式能力注入

`HotkeySettingsControl` 不再读取 `ServicesInitializer.HotKey`。构造函数必须接收 `IHotKeyService`，使插件的权限声明、测试替身和实际调用保持同一条依赖链。控件继续使用 `Long.*` 动态语义资源，因此主题、高对比度与状态色由宿主统一提供。

### UI Kit 与 Contracts 分层

- `LongBetterWindows.PluginSdk`：合同、能力、生命周期、通用异步投递边界；
- `LongBetterWindows.PluginSdk.Wpf`：WPF 控件、多显示器与 DPI 定位辅助；
- Host：通知窗口、锚点编辑器、屏幕采样和搜索实现。

UI Kit 只引用 Contracts SDK，程序集门禁明确禁止反向引用 Host。

### 普通提示走通知能力

Macro 播放失败、Screenshot 截图结果、WindowManager 布局结果均改走 `INotificationService`。需要交互内容或屏幕锚点的 FolderNote 浮层不伪装成普通通知，留给后续专用 Surface 合同。

## 自动化门禁

- UI Kit 程序集必须引用 `LongBetterWindows.PluginSdk` 且不得引用 `LongBetterWindows.Host`；
- `AsyncDeliveryBoundary` 的程序集所有权必须属于 Contracts SDK；
- Macro、Screenshot、WindowManager 的产物不得引用 Host；
- `native-plugin-boundary-audit.json` 必须与实际 `.csproj` 引用逐项一致；
- 热键设置事务回滚、本地化、语义资源测试继续通过。

最终验证结果：WPF UI Kit v1.0.0 NuGet 仅包含目标 DLL、XML 文档、README 与包元数据；四运行时生产验证/确定性打包矩阵 4 / 4；全量自动化 973 / 973；Release 解决方案构建 0 警告、0 错误。
