## 2. 产品目标与边界

- Long 的视觉方向是优雅、华丽、扁平化、动效化，并保持亮色、暗色、高对比度和减少动画模式可用。
- uTools 只作为软件交互逻辑和产品结构参考，不复制视觉资产，也不实现 uTools 插件兼容层。
- 产品保持 Windows 专注、本地优先；当前不引入会员、支付、跨平台或账号云同步。
- 插件市场只允许可信签名的远程 Web 插件；本地 DLL、脚本插件属于明确提示的高信任扩展。

## 5. 新电脑开发环境

建议使用：

- Windows 11 x64
- .NET 8 SDK
- PowerShell 7 或 Windows PowerShell 5.1
- Microsoft Edge WebView2 Runtime
- Visual Studio 2022（安装“.NET 桌面开发”工作负载）或 Rider
- Git for Windows

克隆后先执行：

```powershell
git clone https://github.com/Longyuyeee/Long_BetterWindows.git
cd Long_BetterWindows\repo
dotnet --info
powershell.exe -ExecutionPolicy Bypass -File .\build_test.ps1 -Configuration Release
```

预期结果为 Release 构建 0 警告、0 错误，188 / 188 测试通过。

桌面 UI 自动化必须在已登录的交互式 Windows 桌面运行，不要在无桌面会话的 CI 中强行执行：

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\run-desktop-ui-smoke.ps1 `
  -OutputDirectory .\artifacts\quality\desktop-ui-smoke-handoff

powershell.exe -ExecutionPolicy Bypass -File .\run-isolated-marketplace-transaction.ps1 `
  -OutputDirectory .\artifacts\quality\marketplace-transaction-handoff `
  -NoBuild

powershell.exe -ExecutionPolicy Bypass -File .\run-marketplace-network-resilience.ps1 `
```

## 7. 安全交接

- 仓库只保存公钥、Key ID 和示例配置，不保存真实私钥。
- `LONG_MARKETPLACE_DEPLOY_TOKEN` 必须由新电脑的凭据系统或临时环境变量注入。
- 不要复制旧电脑的测试临时目录；市场事务脚本会在每次运行时创建并删除临时 RSA 私钥。
- 推送前再次检查：

```powershell
git status --short
git diff --check
git diff --cached --stat
git diff --cached --name-only
```

确认暂存区没有发布二进制、私钥和无关个人文件后再提交、推送。
