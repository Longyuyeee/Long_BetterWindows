# Long窗口 组合动作编排协议

> 状态：基础协议阶段
> 主线：`master`
> 发布边界：不属于已冻结的 `v1.9.0-rc.1` 候选包

## 1. 目标

组合动作把现有统一命令连接为可审计的顺序工作流。首要目标不是可视化编辑器，而是先建立稳定的执行契约：

1. 所有命令在执行前完成全量解析和输入兼容性检查。
2. 权限审查覆盖正向命令与补偿命令涉及的全部插件、插件版本和宿主能力。
3. 可变步骤在补偿模式下必须声明逆操作，失败后才能进行确定性的逆序恢复。
4. 工作流身份绑定步骤、输入、参数、插件版本和能力集合，敏感输入只参与 SHA-256 指纹，不写入权限摘要。
5. 执行结果提供逐步骤时间线，供日志、诊断和未来编辑器使用。

## 2. 当前协议

`CommandWorkflowDefinition` 包含：

- 稳定工作流 ID 和展示名称。
- `Stop` 或 `Compensate` 失败策略。
- 1 至 32 个有序步骤。

每个 `CommandWorkflowStep` 包含：

- 唯一步骤 ID。
- `ReadOnly` 或 `Mutating` 副作用分类。
- 正向 `WorkflowCommand`。
- 可选补偿命令；补偿模式中的可变步骤必须提供。

每个命令继续复用 `PluginCommandInvocation`，不建立第二套文本、文件、图片或结构化参数协议。

## 3. 预检与权限边界

`CommandWorkflowPlanner` 在任何命令执行前完成：

1. 工作流 ID、步骤 ID、步骤数量和重复项检查。
2. 正向与补偿命令存在性检查。
3. `command_id` 与目标命令一致性检查。
4. 输入类型与插件声明的 `accepted_inputs` 兼容性检查。
5. 可变步骤补偿完整性检查。
6. 插件 ID、版本和能力集合汇总。
7. 生成小写 64 位 SHA-256 权限审查指纹。

参数字典按键名排序后参与指纹，因此字典插入顺序不会制造不同身份；文本、路径、图片和参数值变化会使指纹失效。插件版本或能力集合变化也会使旧权限审查失效。

## 4. 失败恢复原则

下一实现阶段的执行器遵循以下规则：

1. 预检未通过时零命令执行。
2. `Stop` 模式在首个失败步骤停止，不宣称回滚。
3. `Compensate` 模式只补偿已经成功完成的步骤，并严格逆序执行。
4. 补偿是尽力执行；单个补偿失败不能阻止其余补偿，但最终状态必须是 `CompensationFailed`。
5. 取消与普通失败分别记录；取消发生后仍按既定策略处理已完成步骤。
6. 只读步骤不强制声明补偿，也不能被描述为已回滚的写操作。

`CommandWorkflowExecutor` 每次执行都会重新预检。调用方必须提供 `CommandWorkflowAuthorization`，其工作流指纹、插件 ID、插件版本和能力集合必须与本次预检完全一致，否则以 `Rejected` 结束且零命令执行。

每个插件注册实例具有独立代次，重新注册会获得新值，普通启动/停止状态变化不会使审批失效；无关插件的注册变化也不会打断当前工作流。执行器在每个正向步骤前重新预检；若参与插件升级、重新注册、能力变化或工作流内容变化导致指纹漂移，后续步骤不会执行。此时旧批准不能授权新插件实现执行补偿，结果会明确标记 `CompensationFailed`，保留现场供人工恢复。

工作流定义未来可以持久化，`CommandWorkflowAuthorization` 则明确为当前宿主会话内的一次权限快照，不跨应用重启或参与插件重新注册复用。

补偿不复用已经取消的正向执行令牌，而是为每个逆操作创建独立的 30 秒恢复窗口。单个补偿失败后仍继续执行剩余逆操作，最终通过 `CompensationFailed` 明确暴露部分恢复风险。

执行结果包含单调递增序号、UTC 时间、步骤 ID、阶段和非输入型结果消息。事件不记录命令文本、路径、图片或参数内容。

## 5. 暂不实现

- 可视化流程编辑器和拖拽连线。
- 条件分支、循环、并行分支和跨设备执行。
- 后台无人值守批准。
- 用通用编排补偿替代插件安装或注册表已有的专用事务机制。

这些能力必须在顺序执行、权限审批、取消和补偿时间线稳定后再评估。

## 6. 持久化与来源信任

工作流文档当前使用 Schema v2，包含 `schema_version`、`source` 和 `workflow`。Schema v1 可以迁移，但迁移结果固定为 `legacy-v1` 未信任导入，不继承任何历史可信声明。

来源分为：

- `LocalManaged`：由本机托管仓储创建，只表示来源可追踪。
- `Imported`：从外部文件或模板目录导入，默认 `Untrusted`。
- `TrustedSource`：外部信任策略中的 `source_id` 与规范化工作流定义 SHA-256 精确匹配。

文件内自报 `LocalManaged` 或可信来源不能提升信任等级。定义哈希绑定步骤、命令、补偿、文本、路径、图片和排序后的参数，但不包含当前插件注册代次；执行时仍必须重新预检并取得会话级 `CommandWorkflowAuthorization`。

文本、路径、图片和参数均按潜在敏感输入处理。未来文件仓储默认拒绝静默保存这些字段，只有明确选择包含敏感输入时才允许落盘。
