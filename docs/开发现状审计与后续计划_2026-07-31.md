## 1. 审计结论

Long助手的主体产品方向已经基本对齐最初需求：

- 产品定位已经稳定为 Windows 统一效率入口；
- 参考 uTools 的搜索、命令、插件和快速唤起交互逻辑，但不实现 uTools
  插件兼容；
- 主界面、统一工作区、管理中心、插件市场、设置、主题、动效、响应式布局、
  DPI 和辅助功能已经形成统一工程体系；
- 25 个正式内置插件、42 条命令、四种插件运行形态、生产验证、确定性打包、
  市场信任和回滚工具已经落盘；
- Contracts、Testing、WPF、Web 与 IPC SDK 均已进入 `1.1.0` 版本边界；
- LPWP Widget 已经从协议推进到可见工作台、真实 WebView Surface、参考插件包
  和 IPC 客户端基础。

但项目目前仍不能判定为“完全收口并可正式发布”：

1. 当前 LPWP 成果仍位于串联 Draft PR，没有进入 `master`；
2. PR-C 只完成共享 IPC 客户端基础，Host Broker 服务、目录端点、命令调用、
   取消和 `plugin.open` 尚未完成；
3. PR-D 的 Broker 开关/诊断、兼容门禁和签名参考包尚未完成；
4. 25 项真实桌面插件人工验收仍为 `0 passed / 25 pending / 0 failed`；
5. 物理 DPI、任务栏、读屏、管理员性能、真实下载、干净 Windows 和
   Registry/CDN 回滚仍需要外部环境签核；
6. 当前最新稳定 Release 仍为 `v1.8.0`，最新预发布为 `v1.11.0-rc.2`；
   它们均早于本轮 LPWP 开发，不能代表当前源码。

当前阶段应定义为：

> 产品主体和自动化工程目标基本对齐；LPWP 正在从 PR-B 进入 PR-C；
> 代码可继续开发和评审，但主线整合、跨进程 Broker、真实桌面与发布门禁
> 未关闭，因此 `release_eligible=false`。

实施顺序：

1. Host 引用 `LongBetterWindows.PluginIpc`；
2. 创建 `LongPluginBrokerService` 与连接级状态机；
3. Named Pipe 服务端使用当前用户限制；

- Release、全量测试、IPC 专项和 CI 全绿。

### 阶段 2：PR-C-C 命令调用与取消

实施顺序：

1. `command.invoke` 只调用现有命令编排与能力检查；
2. 参数使用稳定 DTO，不允许 CLR 类型名或任意反序列化；
3. deadline 和取消令牌传递到插件调用链；
4. 同插件默认最多 4 个并发命令；
5. Pipe 断开取消该连接全部未完成请求；
6. 无法取消时丢弃迟到结果；
7. 日志只记录审计 ID、方法、耗时、结果分类，不记录令牌、剪贴板或完整敏感参数。

退出条件：

- 最小客户端可调用一个低风险现有命令；
- 超时、取消、能力拒绝、插件崩溃和断线均映射为标准错误；
- 不引入第二套插件生命周期或权限系统。
