# Long_BetterWindows 设计文档 (Part 2: 插件系统与通信机制)

## 1. 插件分发与加载 (Distribution & Loading)
插件采用标准的 **ZIP 格式** 进行打包（后缀名可设为 `.lpak` 或直接使用 `.zip`）。

*   **内置插件：** 预置在主程序的 `InternalPlugins/` 目录下，首次运行自动解压至 `Plugins/`。
*   **安装/启用逻辑：** 
    1. 用户提供插件压缩包。
    2. 主程序解压至独立子目录。
    3. 扫描 `manifest.json` 校验元数据。
    4. 插件图标出现在“工具箱桌面”，用户双击后触发动态加载。

## 2. 插件包标准结构
```text
/Plugins/[PluginID]
  ├── manifest.json        # 核心配置文件（ID、版本、权限、入口）
  ├── /assets              # 静态资源（图标等）
  ├── /ui                  # UI 布局文件 (XAML/HTML)
  ├── plugin.dll           # 业务逻辑（C# Class Library）
  └── config.json          # 插件持久化配置
```

## 3. 插件清单 (Manifest.json) 规范
```json
{
  "id": "com.long.folder-note",
  "version": "1.0.0",
  "name": "文件夹备注助手",
  "author": "Long",
  "entry_point": "plugin.dll",
  "capabilities": [
    "system.hotkey",
    "shell.context_menu",
    "ui.floating_box"
  ],
  "default_settings": {
    "hotkey": "Alt+M",
    "auto_start": true
  }
}
```

## 4. 通信机制：宿主中转异步总线 (Host-Mediated Async Bus)
插件与主程序通过 **宿主 API (Host API)** 进行交互。

*   **调用流：** `Plugin -> HostAPI(Request) -> HostCore(Action) -> HostAPI(Response) -> Plugin`
*   **特性：**
    1. **异步性：** 所有的 API 调用默认均为异步，防止耗时系统操作阻塞插件 UI。
    2. **冲突检测：** 主程序在注册热键或修改注册表前，会对比所有已启用插件的状态，确保唯一性。
    3. **权限沙盒：** 插件只能调用在 `manifest.json` 中声明过的 `capabilities`。

---

## 5. 本阶段关键备注
> **备注：** 针对“内置插件直接放好”的场景，主程序应具备 **“热更新”** 能力。当主程序检测到插件目录下的 `manifest.json` 版本号提升时，应提示用户或自动重新加载插件，而无需重启主程序。
