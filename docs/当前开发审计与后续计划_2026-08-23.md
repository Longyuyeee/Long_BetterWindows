## 5. 与最初目标的对齐判断

### 5.1 已对齐的部分

- 统一命令入口、键盘优先导航、上下文输入、超级面板和插件市场的产品骨架已经存在。
- 25 个内置插件、42 条命令和 DLL / C# Script / WebView2 三运行时已经形成自有插件平台。
- Long Design System 已覆盖亮暗主题、扁平层级、动效、减少动画、高对比度、DPI、键盘与 UIA 语义基础。
- 插件能力、生命周期、隔离、可信安装升级回滚、更新清单签名和 SHA-256 校验已明显超过普通启动器的范围。
- uTools 仅作为交互与产品组织参考，项目没有走向 uTools 插件兼容层或品牌复刻，符合已确认边界。
- 人工签字型发布门禁已从当前开发主线移除，符合“不需要人工验收”的最新要求。

### 5.2 尚未对齐或尚未自动证明的部分

- 本地、打包、CI 尚未共享一个唯一收口入口，存在命令漂移风险。

- 视觉基准、感知差异、布局几何、DPI×主题×语言、动效关键帧和 UIA 焦点图尚未形成统一自动矩阵，属于 A015-A020。
- 安装器事务、隔离用户环境、非管理员性能预算和重复稳定性尚未形成 P0 的最终自动证据，属于 A021-A024。
- 新 RC 必须等 A010-A024 全部完成后由 A025 从干净提交重新生成；RC17 只能保留为历史候选。
- uTools 对标差距中的空查询首页、声明式匹配、动态指令、结构化结果流、超级面板文件夹/分页、开发者诊断中心、市场内容密度以及图片、二维码、PDF、增强搜索、OCR 等能力仍在 B001-G006。

因此，当前评价是“方向对齐、工程主体成熟、自动验收迁移完成第一段，但尚未收口”，不能写成“完全对齐 uTools”或“稳定版已完成”。

## 6. 下一步唯一任务：A010

### 6.1 已确认的代码差距

当前存在三套相互重复但不完全等价的路径：

1. `build_test.ps1` 默认使用 Debug，只执行 solution 构建和 .NET 测试。
2. `release.ps1` 独立维护 Release 构建、全量测试、publish、打包和冒烟逻辑。
3. `.github/workflows/build.yml` 又分别维护 Build and test 与 Plugin platform 两个 job；后者单独执行插件定向测试、Web SDK 测试和 runtime matrix。

三条路径都没有消费同一个自动收口编排入口。任意一处增加门禁时，其他入口可能遗漏，这已经构成稳定版前的真实流程风险。

### 6.2 A010 设计要求

建立一个仓库级 PowerShell 入口作为唯一真源，名称可在实现时确定，但必须满足以下职责：

- 默认使用 Release，并显式执行依赖恢复、Release 构建和 1457 项全量测试；
- 执行 Web SDK 测试、插件 runtime matrix、插件正向矩阵、LPWP 兼容性与最终收口聚合；
- 统一输出机器可读 JSON，包含源码提交、脏状态、每个阶段状态、证据摘要、产物路径和 SHA-256；
- 对 `failed`、`blocked_environment`、`not_run` 分别传播，禁止把阻断折算为通过；
- 允许 CI 将 TRX、JSON 和诊断日志作为 artifacts 上传，但不得要求人工批准；
- `release.ps1` 在 publish 和打包前调用该入口，不再复制构建/测试门禁；
- `build_test.ps1` 和面向用户的一键脚本调用同一入口，Debug 仅作为显式开发选项；
- `.github/workflows/build.yml` 调用该入口，必要的 job 拆分只能是同一入口的模式参数，不能维护另一套门禁清单；
- 保持 `package-long.ps1`、`打包发布.bat` 的用户体验与安全约束，不静默覆盖同版本产物；
- 新增防漂移测试，确保所有正式入口都引用统一脚本，且 Release 门禁集合不可被无测试删除。

### 6.3 A010 自动验收目标

A010 只有同时满足以下条件才能标记 `completed`：

1. 本地统一入口在普通权限环境可完整运行；若某门禁确需特殊环境，应精确输出 `blocked_environment` 和缺失条件。
2. `build_test.ps1`、`release.ps1`、`package-long.ps1`、`打包发布.bat` 与 GitHub CI 均可追溯到统一入口。
3. 本地与 CI 对同一提交生成相同的门禁 ID 集合，允许时间、绝对路径等非确定字段不同。
4. Release 构建 0 错误；全量测试、Web SDK、runtime matrix、插件矩阵和 LPWP 合同全部通过。
5. 人为篡改报告、删除门禁、制造脏提交或使子阶段失败时，总入口必须非零退出且最终聚合不可发布。
6. 新增自动化测试覆盖成功、代码失败、环境阻断、未运行、报告篡改和入口防漂移。
7. 更新 README、当前状态、总计划与 A010 独立审计文档；代码与文档提交推送后，Repository CI 成功。
