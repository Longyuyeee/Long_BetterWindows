# Long助手严重问题审计与整改计划

> 审计日期：2026-07-27
> 审计起点：`master` / `origin/master` @ `26b5732`（`v1.11.0-rc.2`）
> 范围：主题与颜色、交互性能、25 个内置插件、分离窗口任务栏身份
> 发布判断：`v1.11.0-rc.2` 被真实用户测试阻断，不再作为可发布候选

## 1. 结论

用户报告的四类问题均能在代码或真实运行中找到依据，不是单纯的环境差异：

1. 运行时主题切换只更新颜色资源，没有替换既有画刷实例，造成主体切换而标题栏、控件仍保持旧主题。基础按钮悬停模板还会把主按钮背景改成普通表面色，但保留白色前景。
2. QuickLaunch 在每次输入时同步递归扫描文件和文件内容；本地文件索引还会频繁复制大列表并对完整索引排序。这是交互卡顿的高可信根因。
3. Web 插件初始化在导航和 JS 命令处理器就绪前返回，真实命令存在随机失败或 30 秒超时。DevToolkit 没有命令处理器，PortManager 调用了不存在的桥接方法，WindowManager 指南依赖跨程序集窗口样式并在运行时解析失败。
4. 分离插件窗口沿用宿主进程身份和图标，并设置主窗口为原生 Owner，Windows 任务栏会将其继续视为同一应用。

本轮先修复共性根因和已复现插件故障。候选恢复前仍需完成 5 个高副作用/外部依赖插件的人工功能验收，以及真实任务栏分组观察。

## 2. 已完成整改

### 2.1 UI 与主题

- 主题切换现在重新生成语义画刷和兼容别名，不再只替换 `Color`。
- 主按钮拥有独立 hover/pressed 颜色；基础按钮不再覆盖主按钮背景。
- `Styles.xaml` 中卡片、分段控件和滚动条迁移到动态语义资源。
- DevToolkit 固定深色 CSS 全部迁移到 Long Web UI Kit 变量。
- ScriptCreationDialog 固定深色背景、文本、输入框和按钮迁移到 Long Design System。
- 真实 UI Automation 验证暗色切换亮色后，主体和标题栏同步更新。

### 2.2 性能

- QuickLaunch 搜索增加取消、180 ms 防抖和查询版本校验。
- 文件名及内容递归扫描移到后台线程；窗口关闭时取消未完成搜索。
- 本地文件索引上限从 75,000 调整为 30,000，快照批次从 256 调整为 2,048。
- 查询改为有界最佳匹配，不再为每次输入投影、排序完整索引。
- 空闲测量没有发现持续 CPU 异常；当前高优先级问题集中在交互式磁盘扫描。

### 2.3 插件可靠性

- WebView2 初始化会等待桥接注入和首次导航完成，避免首条命令早于页面处理器。
- DevToolkit 增加 `dev-toolkit.open` 命令处理器。
- PortManager 将错误的 `findOwner` 调用修正为公开 API `findPortOwner`。
- WindowManagerGuide 移除跨程序集 `LongDialog` 查找，改用自身窗口属性和 WindowChrome。
- 修复后 DevToolkit、PortManager、WindowManager 三条真实命令均以退出码 0 完成。

### 2.4 分离窗口任务栏身份

- 分离窗口不再设置主窗口为原生 Owner，只保留应用内返回目标。
- 每个插件使用稳定的 `LongAssistant.Plugin.<plugin-id>` AppUserModelID。
- 每个插件生成确定性独立图标，并在窗口句柄创建后写入任务栏身份。
- 代码与命令冒烟已确认属性写入不再抛异常；最终分组效果仍需在真实任务栏人工确认。

## 7. 第二轮高副作用插件整改

2026-07-27 对 ColorPicker、FolderNote、Macro、Screenshot、Translate 完成逐文件审计：

1. Translate 原命令处理器没有等待网络请求，网络失败仍可能向宿主返回成功。现已等待翻译完成并返回真实结果；在线真实命令退出码为 0，耗时约 2.9 秒。
2. FolderNote 原命令在没有有效文件夹时仍返回成功，异步 ADS 保存由 `Action<string>` 变成了不可观察的 `async void`。现已返回真实目标解析结果，等待保存完成，失败时保留窗口并提示；停用插件会关闭活动 HUD。
3. Screenshot 全屏命令原先在截图和剪贴板写入前返回成功。现已等待捕获及写入，并将失败反馈给命令调用方。区域截图仍是明确的交互式“已开始”语义。
4. Macro 的绝对鼠标输入直接使用像素坐标，未转换到 Windows 要求的 0–65535 虚拟桌面坐标，可能造成回放点击偏位；循环状态还会被单轮播放改回 Idle，无法可靠停止。现已使用虚拟桌面归一化、统一取消令牌，并在钩子安装失败、空宏或忙碌状态下返回失败。
5. ColorPicker 在桌面 DC 或光标采样失败时不再留下无响应取色窗口。

## 8. 第三轮性能与启动状态审计

2026-07-27 继续针对“软件运行后电脑卡顿”审计启动链路和 QuickLaunch：

1. 确认统一命令执行器此前会把按需启动等同于用户启用，并在每次首次调用插件时持久写入 `auto_start=true`。插件一旦被命令中心或工作流使用，后续启动便可能永久增加自动启动项。现已为 `PluginRegistry.StartPluginAsync` 增加明确的持久化参数；插件管理页主动启用仍会保存设置，命令执行仅在本次会话启动插件，不再改变下次启动策略。
2. QuickLaunch 首次打开此前仍在 UI 线程同步递归枚举开始菜单。现已改为窗口显示后在后台发现应用，应用列表完成后自动刷新当前查询。
3. QuickLaunch 文件名搜索此前只有命中结果后才检查取消，因此无匹配的大目录仍可能长时间占用后台线程。现改为逐候选检查取消，并将每个搜索根的候选上限设为 5,000。
4. QuickLaunch 内容搜索现限制为 500 个候选文件、单文件最大 1 MiB，避免误读超大日志或数据文件造成瞬时内存和磁盘压力；窗口关闭时会释放搜索取消令牌。

真实 Release 空闲探针结果：

- 宿主启动日志：`10:46:22.518`；25 个插件运行时就绪：`10:46:28.971`，约 6.45 秒。
- 5 秒空闲采样：工作集 206.4 MB，私有内存 172.8 MB，25 个插件、42 条命令。
- 探针进程正常以退出码 0 自行结束；包含 5 秒空闲等待的进程总时长约 13.88 秒。
- 当前开发输出目录中 25 个插件均被判定为自动启动，其中一部分是旧命令执行语义遗留的 `config.json`。本轮已经阻止新增污染，但尚未证明现有用户配置能够无损迁移。

性能发布判断仍为 **P0 未关闭**。下一批按以下顺序推进：

1. 为自动启动设置增加来源/版本信息，区分用户显式启用与旧版本命令调用污染，并提供一次性兼容迁移。
2. 将非后台、非热键插件从“启动时实例化”推进到“命令首次调用时实例化”，降低 25 个程序集全量加载的启动成本。
3. 建立冷启动、插件运行时就绪、5 秒空闲工作集和私有内存的重复采样门禁；不能再只依赖单次低于 200 MB 的历史结果。
4. 在大目录样本上记录 QuickLaunch 首次显示、连续输入、取消查询和无匹配查询的 P50/P95 延迟。
