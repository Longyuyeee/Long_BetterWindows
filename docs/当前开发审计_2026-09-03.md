## 4. CI 失败与修复审计

A010 在最终成功前出现过两次真实远端失败，均已定位并通过后续提交修复，没有以重跑代替整改：

1. [运行 33761087509](https://github.com/Longyuyeee/Long_BetterWindows/actions/runs/33761087509) 绑定 `a965eb0`，失败原因是递归脚本固定调用 Windows PowerShell 5.1，而 CI 顶层使用 PowerShell 7，导致无 BOM 中文脚本发生编码解析错误。
2. [运行 33761614380](https://github.com/Longyuyeee/Long_BetterWindows/actions/runs/33761614380) 绑定 `b5a153a`，继续暴露三项跨运行时差异：旧测试仍断言固定 `powershell` 调用、PowerShell 7 的只读 `$IsWindows` 与脚本变量冲突、参考 Widget 在不同压缩运行时下哈希不一致。
3. `ec7e499` 将递归收口步骤绑定到当前 PowerShell 主机，通过独立 JSON 文件传递原生性能预检结果，并有意保留参考 Widget 的 Windows PowerShell 5.1 压缩基线以维持确定性哈希。随后运行 `33762421494` 首次完整通过。

这些失败已经转化为防回归测试和明确的运行时边界，当前没有遗留的 A010 代码失败。
